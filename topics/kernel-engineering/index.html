Kernel Engineering

目标：具备申请 Apple kernel engineer 岗位所需的内核功底。路线：先用 Linux 把内核基础打牢（公开资料最丰富、能在 QEMU 里随便拆），每一阶段同时对照 XNU（Mach + BSD + IOKit，Apple 的内核不是 Linux），最后一阶段切换到 Apple 路线。

Goal: the kernel fundamentals an Apple kernel-engineer application needs. Route: build the basics on Linux first (the richest public material, and you can take it apart freely in QEMU), compare every phase with XNU (Mach + BSD + IOKit — Apple's kernel is not Linux), and switch to the Apple track in the last phase.

读者画像：会 C、知道进程/虚拟内存/系统调用是什么，但没有读过内核源码。每个 phase 大约 1–2 周（每天 1–2 小时）。本课程固定在 Linux v7.3.1 与 XNU xnu-12377.121.6（2026-11-05 核对），版本与核对清单见 docs/authoring/KERNEL_SYLLABUS.md。
Reader: knows C and what processes, virtual memory and system calls are, but has not read kernel source. Each phase is about 1–2 weeks at 1–2 hours a day. The topic is pinned to Linux v7.3.1 and XNU xnu-12377.121.6 (checked 2026-11-05); the pins and the verification list are in docs/authoring/KERNEL_SYLLABUS.md.

阶段

Phases

  1. 0Foundations
    C 系统编程、ARM64 基础（Apple Silicon）、工具链、在 QEMU 里编译并启动 LinuxC systems programming, ARM64 basics (Apple Silicon), toolchain, build and boot Linux in QEMU
  2. 1Boot & Processes
    boot chain、进程/线程模型、上下文切换、调度（CFS/EEVDF ↔ Mach scheduler）Boot chain, process/thread model, context switch, scheduling (CFS/EEVDF ↔ Mach scheduler)
  3. 2Memory
    虚拟内存、ARM64 页表、缺页路径、分配器（buddy/slab ↔ Mach VM/zalloc）Virtual memory, ARM64 page tables, the page-fault path, allocators (buddy/slab ↔ Mach VM/zalloc)
  4. 3Concurrency & IPC
    spinlock/mutex/RCU、内存序；Mach port 与消息Spinlocks, mutexes, RCU, memory ordering; Mach ports and messages
  5. 4Syscalls, VFS & Filesystems
    系统调用入口、VFS 层次、ext4 ↔ APFS、块 I/OSyscall entry, the VFS layers, ext4 ↔ APFS, block I/O
  6. 5Device Drivers
    Linux driver model / devicetree ↔ IOKit / DriverKit，中断与 DMALinux driver model / devicetree ↔ IOKit / DriverKit, interrupts and DMA
  7. 6Debugging & Tooling
    ftrace/perf/kgdb/crash ↔ lldb+KDP/dtrace/panic log；读内核源码的方法ftrace/perf/kgdb/crash ↔ lldb+KDP/dtrace/panic logs; how to read kernel source
  8. 7Security & Hardening
    KASLR、PAN/PXN、PAC、PPL/SPTM、sandbox、code signingKASLR, PAN/PXN, PAC, PPL/SPTM, sandbox, code signing
  9. 8XNU & the Apple Track
    编译 XNU、Darwin 内部阅读计划、作品项目（Linux module + DriverKit driver）、Apple 面试环节Build XNU, a Darwin internals reading plan, a portfolio project (Linux module + DriverKit driver), the Apple interview loop

实战路线

Practical track

九个阶段学完之后的第二条路线，目标是让你有可以写进简历、能在面试里讲的内核工作经历。每个实战阶段给的是任务和验收标准，不是逐步命令：往真实的邮件列表发补丁，查出埋好的 bug，写出别人可以检查的记录。每个阶段约 2–4 周。

A second route for after the nine phases. Its aim is kernel work you can put on a CV and talk about in an interview. A practical stage gives you a task and acceptance criteria, not step-by-step commands: post a patch to a real mailing list, track down planted bugs, and leave a record that others can check. Each stage takes about 2–4 weeks.

  1. 1Upstream Workflow & First Patch
    找一处真实的小缺陷，写成补丁发到内核邮件列表，回应评审；交付物是 lore 上的讨论串链接Find a small real defect, post it as a patch to a kernel mailing list and answer the review; the deliverable is the link to the thread on lore
  2. 2The Debugging Range
    四个埋了 bug 的模块，只给症状：用 KASAN、lockdep、kmemleak、KCSAN 找出根因并修复；交付物是四份事后分析Four modules with planted bugs and only a symptom each: find and fix the root causes with KASAN, lockdep, kmemleak and KCSAN; the deliverable is four post-mortems
  3. 3Fix a Real Bug
    从公开的 syzbot 报告里选一个真实的内核 bug，写出根因报告并把修复发到邮件列表Pick a real kernel bug from the public syzbot reports, write a root-cause report and post a fix to the list    筹备中Planned
  4. 4A Complete Driver from Nothing
    从零写一个完整的驱动：代码、测试和设计说明放在一个仓库里Write a complete driver from nothing: code, tests and a design note in one repository    筹备中Planned
  5. 5A Performance Investigation
    一次性能调查：带前后数据的报告和可重复的基准脚本One performance investigation: a report with before and after numbers, and benchmark scripts that can be rerun    筹备中Planned
  6. 6CI, Bisection & Backports
    搭一条能编译、启动、测试内核的流水线，做一次 bisect 和一个 stable 回移补丁Build a pipeline that builds, boots and tests a kernel; do one bisection and one stable backport    筹备中Planned
  7. 7The Apple Side
    三份 panic 分析，加一个系统扩展或一份 XNU 调度器阅读报告Three panic analyses, plus a system extension or a reading report on the XNU scheduler    筹备中Planned
  8. 8Portfolio & Interviews
    把前面的交付物汇成一页作品集，做三次代码评审练习，准备五个排错故事Gather the earlier deliverables into a portfolio page, do three code-review exercises and prepare five debugging stories    筹备中Planned
