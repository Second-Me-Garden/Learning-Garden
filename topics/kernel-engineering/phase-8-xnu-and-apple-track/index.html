  • 为 Apple 面试的各个环节（电话面、编码、操作系统基础、调试、系统设计）准备好可讲的例子。

1. 从源码构建 XNU

本节讲获取 apple-oss-distributions/xnu、匹配版本的 KDK 与 SDK，以及按仓库 README 中的 make 参数（如 KERNEL_CONFIGS、ARCH_CONFIGS）构建。

2. Darwin 内部阅读计划

本节给出有序文件清单：osfmk/arm64/start.s → osfmk/kern/startup.c → osfmk/kern/sched_prim.c → osfmk/ipc/ipc_kmsg.c → osfmk/vm/vm_fault.c → bsd/kern/kern_exec.c → bsd/vfs/vfs_lookup.c → iokit/Kernel/IOService.cpp。

3. 作品集项目

本节规划一个 Linux 内核模块（如字符设备 + procfs 统计），再加一个 DriverKit 驱动或用户态 Mach IPC 工具，并写清设计说明。

4. 跟踪 XNU 的版本变化

本节讲如何在 opensource.apple.com 的版本发布与 xnu 仓库的 tag 之间做 diff，从变化中读出新机制。

动手实验

  • macOS：克隆 xnu 仓库，按 README 构建一次（或至少跑通依赖准备），记录用到的 SDK 与 KDK 版本。
  • macOS：用 git log/git diff 对比 xnu 两个相邻 tag 中 osfmk/ipc/ 的变化，写一段摘要。
  • Linux（QEMU）：完成作品集中的内核模块，附带测试脚本与 README。
  • macOS：用 Xcode 的 DriverKit 模板创建一个最小 dext，或写一个用 mach_msg 通信的客户端/服务端工具。

自测

1. XNU 由哪三大部分组成？

XNU = Mach（osfmk/：任务、线程、IPC、VM）+ BSD（bsd/：POSIX、VFS、网络）+ IOKit（iokit/：C++ 驱动框架）。DriverKit 是用户态的驱动框架，不在内核中。

2. 在 xnu 源码树中，Mach IPC 的核心实现位于哪个目录？

Mach 部分都在 osfmk/ 下：IPC 在 osfmk/ipc/，消息收发的 trap 入口在 osfmk/ipc/mach_msg.c。
