Security & Hardening 安全与加固：KASLR、PAN/PXN、PAC、PPL/SPTM、sandbox、code signing

内核是攻击者的终极目标：一个内核内存破坏漏洞往往意味着整机沦陷。Apple 在硬件和内核两层叠加了大量缓解措施（PAC、PPL/SPTM、kalloc_type、代码签名），内核工程师写的每一行代码都要放在这套防御体系里考量。

目标

读完并做完实验后，你应该能：
  • 为内核写出一个简单威胁模型：攻击面在哪里、攻击者拿到什么原语、各项缓解措施阻断哪一步。
  • 解释 KASLR、W^X、PXN、PAN、stack canary、CFI 各自防御的攻击手法。
  • 说明 ARM PAC 如何用 pacia 签名、autia 校验指针，以及 PPL/SPTM 为什么要把页表保护从内核本身剥离出来。
  • 对比 XNU 的 MACF/Sandbox/AMFI/SIP 与 Linux 的 LSM/SELinux，并能读懂一篇内核 CVE 分析文章。

核心概念

1. 内核威胁模型

本节讲攻击面（系统调用、IOKit 用户客户端、文件系统、网络）与典型利用链：内存破坏 → 读写原语 → 提权。

2. KASLR 与 W^X / PXN / PAN

本节讲地址随机化，以及页表权限位如何阻止内核执行或直接访问用户内存。

3. stack canary 与 CFI

本节讲栈保护（CONFIG_STACKPROTECTOR）、前向边 CFI（Clang kCFI、ARM BTI）分别防御的控制流劫持方式。

4. ARM Pointer Authentication（PAC）

本节讲 pacia/autia/pacibsp 如何把签名放进指针高位，以及 Apple arm64e ABI 对它的大规模使用。

5. PPL 与 SPTM

本节讲 Apple 把页表与代码签名关键数据的修改权限从普通内核代码中隔离出来的设计（PPL，以及较新芯片上的 SPTM）。

6. kalloc_type 与堆隔离

本节讲 XNU 按类型隔离内核堆分配以对抗 UAF 类型混淆，并对照 Linux 的 slab 加固选项。

7. 强制访问控制与代码签名

本节讲 XNU 的 MACF 钩子、Sandbox（Seatbelt）、AMFI 代码签名校验与 SIP，并以 Linux LSM/SELinux 作对照。

8. 读 CVE 分析

本节给出阅读内核漏洞分析文章的框架：漏洞根因、触发路径、利用原语、被哪项缓解阻断或绕过、补丁如何修复。

动手实验

  • Linux（QEMU）：多次启动后对比 /proc/kallsyms 中 start_kernel 的地址（以 root 读取），观察 KASLR。
  • Linux（QEMU，-cpu max）：用 clang -mbranch-protection=pac-ret 编译一个用户态小程序，反汇编查看 paciasp/autiasp。
  • macOS：用 csrutil status 查看 SIP 状态，用 codesign -dv --entitlements - /bin/ls 查看签名与 entitlements。
  • 挑一篇 Project Zero 的 XNU 漏洞分析，按「根因 → 原语 → 缓解」三栏做笔记。

自测

1. ARM PAC 的签名（PAC 值）存放在哪里？

64 位虚拟地址并不使用全部 64 位，PAC 利用这些高位存放签名；autia 等指令校验成功会去掉签名，失败则使指针失效。

2. PAN（Privileged Access Never）开启后阻止的是什么？

PAN 阻止 EL1 直接读写 EL0 可访问的页面，内核只能经由 copyin/copy_from_user 等受控路径访问；禁止内核执行用户页的是 PXN。
