Concurrency & IPC 并发与 IPC：spinlock/mutex/RCU、内存序；Mach port 与消息

内核里任何共享数据都可能同时被多个 CPU 和中断处理程序访问，锁、原子操作和内存序决定了代码是否正确。XNU 又是一个以 Mach 消息为骨架的内核：launchd、XPC、IOKit 用户客户端都建立在 Mach port 之上，不懂 port 和 mach_msg 就读不懂 Darwin 的大半代码。

目标

读完并做完实验后，你应该能：
  • 根据「能否睡眠、读写比例、临界区长度」在 spinlock、mutex、rwsem、RCU 之间做出选择，并说出理由。
  • 解释 acquire/release 语义，并说清它们在 ARM64 上对应 ldar/stlr 和 dmb 的哪种用法。
  • 画出一次 mach_msg 发送与接收的路径，区分 send right、receive right、send-once right。
  • 用 Linux 的 pipe、futex、signal 对照说明 Mach IPC 在设计上的不同取舍。

核心概念

1. spinlock、mutex、rw_semaphore

本节对比忙等锁与可睡眠锁的适用场景，以及持有 spinlock 时为什么不能睡眠。

2. 原子操作与内存序

本节讲 acquire/release、smp_load_acquire/smp_store_release，以及 ARM64 弱内存模型下 dmb ish 的作用。

3. RCU（Read-Copy-Update）

本节讲读者无锁、写者复制后等待宽限期（synchronize_rcu/call_rcu）的机制，以及 XNU 中对应的 SMR。

4. per-CPU 数据

本节讲用 DEFINE_PER_CPU（Linux）与 PERCPU_DATA（XNU）避免共享，以及访问时为什么要关抢占。

5. 锁正确性检查：lockdep 与 XNU lck_*

本节讲 lockdep 如何在运行时发现锁顺序反转，以及 XNU lck_mtx_t/lck_spin_t/lck_rw_t 的接口与锁组。

6. Mach port 与 mach_msg

本节讲 port 作为内核管理的消息队列、port 名字空间，以及 mach_msg 一次调用完成发送和/或接收。

7. port rights 与 XPC

本节讲 receive/send/send-once 三种权限如何在消息中传递，以及 XPC 和 launchd 服务查找如何建立在这些权限之上。

8. 对照：Linux IPC（pipe、futex、signal）

本节以 pipe、futex（对照 XNU 的 ulock）、signal 为例，说明 Linux 在「无统一消息原语」下如何组合出 IPC。

动手实验

自测

1. 持有 spinlock 时调用可能睡眠的函数（例如 GFP_KERNEL 的 kmalloc），主要问题是什么？

spinlock 的设计前提是临界区短且不睡眠；持锁期间抢占被关闭，睡眠会导致等锁的 CPU 空转甚至死锁。要睡眠请用 mutex。

2. 一个 Mach port 的 receive right 最多可以同时被几个 task 持有？

每个 port 只有一个 receive right（单一接收者）；send right 可以有很多个，分布在不同 task 中。
