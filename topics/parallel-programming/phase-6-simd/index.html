1. 一个核里的数据并行：寄存器、车道与元素宽度

1. Data parallelism inside one core: registers, lanes and element widths

Phase 0 讲 Flynn 分类时说过，多核是 MIMD，每个核里又有 SIMD：一条指令作用在一组数据上。AArch64 的 SIMD 叫 Advanced SIMD，通称 NEON。它有 32 个向量寄存器 v0–v31，每个固定 128 位。同一个寄存器可以按不同的元素宽度切成车道（lane）：16 条 8 位、8 条 16 位、4 条 32 位或 2 条 64 位。一条 fadd.4s 把两个寄存器的 4 条 32 位车道两两相加，车道之间互不进位、互不干扰。.4s 里的 4 是车道数，s 是 single，即 32 位；.2d 是 2 条 64 位，.16b 是 16 条 8 位。

When Phase 0 covered Flynn’s taxonomy, it said a multicore CPU is MIMD and each core contains SIMD: one instruction acting on a group of data. AArch64’s SIMD is called Advanced SIMD, commonly NEON. It has 32 vector registers, v0–v31, each a fixed 128 bits. The same register can be cut into lanes of different element widths: 16 of 8 bits, 8 of 16 bits, 4 of 32 bits or 2 of 64 bits. One fadd.4s adds the 4 32-bit lanes of two registers pairwise, with no carry and no interference between lanes. In .4s the 4 is the lane count and s means single, 32 bits; .2d is 2 lanes of 64 bits, .16b is 16 lanes of 8 bits.

在 C 里写 NEON 用 intrinsics（内建函数），头文件 <arm_neon.h>，由 Arm 的 ACLE 规范定义。类型名说出形状：float32x4_t 是 4 个 float，uint8x16_t 是 16 个字节。函数名的规律是「操作 + 可选的 q + 元素类型」：q 表示 128 位的整个寄存器，没有 q 是 64 位的一半。本页用到的四个：vld1q_f32 从内存读 4 个 float，vfmaq_f32(acc, a, b) 每条车道算 acc + a·b，vaddq_f32 逐车道相加，vaddvq_f32 把 4 条车道加成一个数（v 表示 across vector，横跨整个向量）。

In C you write NEON with intrinsics from the header <arm_neon.h>, defined by Arm’s ACLE specification. Type names state the shape: float32x4_t is 4 floats, uint8x16_t is 16 bytes. Function names follow “operation + optional q + element type”: q means the whole 128-bit register, and no q means the 64-bit half. The four used on this page: vld1q_f32 reads 4 floats from memory, vfmaq_f32(acc, a, b) computes acc + a·b in every lane, vaddq_f32 adds lane by lane, and vaddvq_f32 adds the 4 lanes into one number (the v means across the vector).

2. 车道之外的第二个维度：延迟、吞吐和独立的累加器

2. The second dimension beyond lanes: latency, throughput and independent accumulators

车道让一条指令做 4 份工作，但这还不够。一条浮点指令从发出到结果可用要等几个周期（延迟），而核每个周期又能发出不止一条（吞吐）。如果每一步都要用上一步的结果，核只能等延迟。Phase 0 的数组求和用四个累加器把单线程提高了 3 倍，道理相同。Lab B 的标量链和 Lab A 的两个 NEON 版本在本机测出的数字把这一点拆成了三级（n = 4096，放得进 L1）：

Lanes let one instruction do 4 pieces of work, but that is not the whole story. A floating-point instruction takes several cycles from issue until its result is usable (latency), and the core can issue more than one per cycle (throughput). If every step needs the previous step’s result, the core can only wait out the latency. The four accumulators in Phase 0’s array sum made one thread 3 times faster for the same reason. The numbers measured on this Mac, Lab B’s scalar chain and Lab A’s two NEON versions, split this into three levels (n = 4096, fits L1):

  • 标量，一条 fmadd 链（-fno-vectorize，Lab B）：2969 ns 做 4096 次，每次约 0.72 ns。每条 fmadd 都要等上一条的 s0，这 0.72 ns 就是一次乘加的延迟（从测量推出）。
  • Scalar, one fmadd chain (-fno-vectorize, Lab B): 4096 of them in 2969 ns, about 0.72 ns each. Every fmadd waits for the previous one’s s0, so the 0.72 ns is the latency of one multiply-add (inferred from the measurement).
  • NEON，一个向量累加器（neon1）：748 ns 做 1024 条 fmla.4s，每条约 0.73 ns，和标量的一次几乎一样，但每条做了 4 份。车道带来了约 4 倍。
  • NEON, one vector accumulator (neon1): 1024 fmla.4s in 748 ns, about 0.73 ns each, nearly the same as one scalar step, but each does 4 pieces of work. Lanes bought about a factor of 4.
  • NEON，四个向量累加器（neon4）：187–211 ns（三次运行的中位数）。四条互不依赖的链可以同时在流水线里，每 0.73 ns 左右完成 4 条 fmla.4s。独立的链又带来了约 3.5–4 倍。
  • NEON, four vector accumulators (neon4): 187–211 ns (medians of three runs). Four chains that do not depend on each other can be in the pipeline together, completing about 4 fmla.4s every 0.73 ns. Independent chains bought another factor of about 3.5–4.

所以「用 SIMD」有两个旋钮：每条指令几条车道，以及同时有几条互不依赖的链。对照 -fno-vectorize 的标量链（Lab B），只拧第一个，你只拿到 4 倍；两个都拧，同一个核在 L1 里拿到 14–16 倍。vDSP_dotpr 还要再快一点（156 ns），它的实现不公开，实验机上 lldb 附加进程被拒绝，没能读到它的内层循环，所以本页不猜它多用了什么。

So “using SIMD” has two knobs: how many lanes per instruction, and how many independent chains at once. Against the -fno-vectorize scalar chain (Lab B), turn only the first and you get 4 times; turn both and the same core gets 14–16 times in L1. vDSP_dotpr is a little faster still (156 ns). Its implementation is not public, and on the lab Mac lldb was refused permission to attach, so its inner loop could not be read and this page does not guess what more it does.

  2. Step 2, neon1: one fmla.4s does a multiply-add in each of 4 lanes, so the chain shrinks to 1024 steps. The latency per step barely changes, so the time falls to a quarter: that is the factor of 4 the lanes buy.

3. 自动向量化，以及「向量化了」到底说明了什么

3. Auto-vectorization, and what “vectorized” actually tells you

clang 的 loop vectorizer 在 -O2 下默认开启：它把一个循环改写成一次处理 VF 个元素（vectorization width），再把 IC 份这样的工作交错排开（interleaved count），好让几条链同时进行。它是否成功、为什么失败，可以用三个参数让它自己说：

clang’s loop vectorizer is on by default at -O2. It rewrites a loop to handle VF elements at a time (the vectorization width), then interleaves IC copies of that work (the interleaved count) so that several chains run at once. Whether it succeeded, and why it failed, it will tell you itself through three flags:

  • -Rpass=loop-vectorize：报告向量化成功的循环，带上 VF 和 IC。
  • -Rpass=loop-vectorize: reports loops that were vectorized, with VF and IC.
  • -Rpass-missed=loop-vectorize：报告没向量化的循环，只说「没有」。
  • -Rpass-missed=loop-vectorize: reports loops that were not vectorized, saying only that they were not.
  • -Rpass-analysis=loop-vectorize：说明原因，例如 Cannot vectorize potentially faulting early exit loop（提前退出）、Backward loop carried data dependence（真正的循环携带依赖）、cannot identify array bounds（间接下标）。这一个最有用。
  • -Rpass-analysis=loop-vectorize: gives the reason, such as Cannot vectorize potentially faulting early exit loop (an early exit), Backward loop carried data dependence (a true loop-carried dependence) or cannot identify array bounds (an indirect index). This one is the most useful.

Reading these reports with Apple clang 21, two things differ from what older material says, and both were measured:

  • 可能重叠的指针不再挡住向量化。void scale(float *dst, const float *src, …) 这样的循环照样报告 vectorized loop：编译器在循环前插入运行时检查，两段内存不重叠时走向量版本，重叠时走标量版本。restrict 的作用是告诉编译器不必检查，省掉这段检查代码，而不是让循环「能」向量化。
  • Possibly overlapping pointers no longer block vectorization. A loop like void scale(float *dst, const float *src, …) still reports vectorized loop: the compiler inserts a run-time check before the loop and runs the vector version when the two ranges do not overlap, the scalar one when they do. What restrict does is tell the compiler it need not check, removing that code; it is not what makes the loop vectorizable.
  • 不加 -ffast-math 的 float 归约也报告 vectorized loop (vectorization width: 4, interleaved count: 4)。但汇编显示，乘法进了 fmul.4s，16 次加法却仍然是一条按源代码顺序排开的 fadd s0, s0, … 链（Lab B 贴出了这段汇编）。这叫 in-order（strict）reduction：向量化器只能做到不改变加法顺序的那一部分。速度从 2.76 升到 4.44 GFLOP/s，因为链上每一步从 fmadd 换成了更短的 fadd，而重排后的写法是 43 GFLOP/s。所以「报告说向量化了」只说明某些指令变成了向量指令，不说明关键路径变短了；要看汇编，要量时间。
  • A float reduction without -ffast-math also reports vectorized loop (vectorization width: 4, interleaved count: 4). Yet the assembly shows that the multiplies went into fmul.4s while the 16 additions are still one chain of fadd s0, s0, … in source order (Lab B pastes this assembly). This is an in-order (strict) reduction: the vectorizer can do only the part that leaves the order of additions unchanged. Speed rises from 2.76 to 4.44 GFLOP/s because each step on the chain changed from fmadd to the shorter fadd, while the reassociated version runs at 43 GFLOP/s. So “the report says vectorized” only means some instructions became vector instructions, not that the critical path got shorter; read the assembly and measure.

还有一类循环不是参数或改写能修好的：a[i] = a[i-1] + a[i]（前缀和）的每一步都要用上一步刚写的值，报告是 Backward loop carried data dependence。这里要换算法（分块前缀和），不是换编译选项。

And some loops no flag or rewrite of the same loop can fix: in a[i] = a[i-1] + a[i] (a prefix sum) every step needs the value the previous step just wrote, and the report is Backward loop carried data dependence. That calls for a different algorithm (a blocked prefix sum), not a different compiler option.

4. 浮点归约为什么需要重排许可

4. Why a floating-point reduction needs permission to reassociate

整数加法满足结合律，(a + b) + c 与 a + (b + c) 总是相等，所以 int 求和随便拆成几条链都行。IEEE 754 浮点加法每做一次都要舍入，结合律不成立：(1e8f + 1.0f) - 1e8f 是 0，而 1.0f + (1e8f - 1e8f) 是 1（本机实测）。C 标准要求按源代码的顺序求值，所以把 s += a[i]·b[i] 拆成 16 个部分和，等于换了一个程序，编译器默认不能做。

Integer addition is associative, so (a + b) + c always equals a + (b + c), and an int sum can be split into any number of chains. IEEE 754 floating-point addition rounds after every operation, so associativity fails: (1e8f + 1.0f) - 1e8f is 0, while 1.0f + (1e8f - 1e8f) is 1 (measured on this Mac). The C standard requires evaluation in source order, so splitting s += a[i]·b[i] into 16 partial sums is a different program, which the compiler may not produce by default.

给许可有三种粒度，从窄到宽：

Permission comes at three granularities, narrowest first:

  • 自己写多个累加器。Lab A 的 neon4 就是：顺序是你定的，编译器照做。
  • Write the accumulators yourself. Lab A’s neon4 does this: you choose the order, and the compiler follows it.
  • #pragma clang fp reassociate(on) 放在函数体或复合语句开头，只对那一块允许重排加法。Lab B 用它把同一个循环从 4.44 提到 43.25 GFLOP/s，汇编变成四条 fmla.4s 链。有个细节值得看：只开重排时，编译器把累加器初始化成 -0.0（movi.4s v1, #128, lsl #24，即 0x80000000），因为没有允许忽略零的符号时，-0.0 才是加法的单位元。
  • #pragma clang fp reassociate(on) at the start of a function body or compound statement allows reordering additions in that block only. Lab B uses it to take the same loop from 4.44 to 43.25 GFLOP/s, and the assembly becomes four fmla.4s chains. One detail is worth a look: with only reassociation enabled, the compiler initialises the accumulators to -0.0 (movi.4s v1, #128, lsl #24, which is 0x80000000), because without permission to ignore the sign of zero, -0.0 is the identity of addition.
  • -ffast-math 对整个文件生效，同时还假设没有 NaN 和无穷、不区分 ±0 等。它也会产生 fmla.4s 的四链版本，但代价是整个翻译单元的语义都变了，只为一个循环开它太宽。
  • -ffast-math applies to the whole file and also assumes there are no NaNs or infinities, that ±0 need not be told apart, and more. It too produces the four-chain fmla.4s version, but the semantics of the entire translation unit change, which is too broad for the sake of one loop.

Once a single float accumulator grows past 2²³ ≈ 8.39 million, neighbouring representable numbers are 1 or more apart, so each added value of 0.125–3 is rounded heavily; split 16 ways, each partial sum is a sixteenth the size and the rounding error is far smaller. This is one concrete example that reordering changes the result, not a proof that reordering is always more accurate: with other data the error can go the other way. When you need bit-for-bit reproducible results, such as the golden values of a test, fix one order.

横向归约（horizontal reduction）是最后把一个向量的几条车道加成一个数。vaddvq_f32 编成两条成对相加：faddp.4s v0, v0, v0 把相邻车道两两相加，faddp.2s s0, v0 再加一次。车道之间的操作比逐车道的操作贵，所以归约放在循环外做一次，循环里只做逐车道的 fmla。

A horizontal reduction is the final step that adds the lanes of a vector into one number. vaddvq_f32 compiles to two pairwise adds: faddp.4s v0, v0, v0 adds neighbouring lanes in pairs, and faddp.2s s0, v0 adds once more. Operations across lanes cost more than lane-by-lane ones, so the reduction happens once after the loop, and the loop body does only lane-by-lane fmlas.

5. 对齐，以及 AoS 与 SoA

5. Alignment, and AoS versus SoA

对齐。在 AArch64 上，对普通内存，vld1q_f32 接受任何 4 字节对齐的 float 地址，不要求 16 字节对齐；不像早期的 x86 SSE 那样要分 movaps 和 movups。实测（Lab A 的 neon4 改成从偏移后的地址开始读，n = 4096；这个变体程序本页未列出）：把起点偏移 0、4、8、12、16 字节，预热后的中位数都在 186.1–186.9 ns；在 L2 尺寸上，偏移 4 字节比对齐的慢约 1.7 %（15599 对 15338 ns），推测是因为每 8 次 16 字节读取有 1 次跨过 128 字节缓存行。结论：不必为 NEON 刻意对齐，但大数组用 aligned_alloc(128, …) 按缓存行对齐几乎没有成本，还能避开 Phase 0 讲的伪共享。另外注意，每次运行里第一组测量都偏慢（偏移 0 时 215 ns、偏移 1 时 195 ns），和偏移无关，是预热，所以要先预热再取中位数。

Alignment. On AArch64, for normal memory, vld1q_f32 accepts any 4-byte-aligned float address and does not require 16-byte alignment; there is no split like early x86 SSE’s movaps versus movups. Measured (Lab A’s neon4 changed to start reading at an offset address, n = 4096; this variant of the program is not shown): with the start offset by 0, 4, 8, 12 and 16 bytes, the medians after warm-up all lie between 186.1 and 186.9 ns; at the L2 size, a 4-byte offset is about 1.7 % slower than aligned (15599 against 15338 ns), presumably because 1 in 8 of the 16-byte loads crosses a 128-byte cache line. Conclusion: there is no need to align specially for NEON, but aligning large arrays to the cache line with aligned_alloc(128, …) costs almost nothing and also avoids the false sharing of Phase 0. Note too that the first measurement in each run was slower (215 ns at offset 0, 195 ns at offset 1) regardless of offset: that is warm-up, which is why you warm up first and then take the median.

AoS 与 SoA。把点存成 struct P { float x, y, z; } p[n] 是 AoS（array of structures），内存里是 x y z x y z …；存成三个数组 x[n]、y[n]、z[n] 是 SoA（structure of arrays）。一次 16 字节的向量读取在 AoS 上拿到的是 x0 y0 z0 x1，车道里混着不同字段，不能直接算。编译器的办法是 ld3.4s：一次读 48 字节，按三个一组拆开到三个寄存器。对 p[i].x 求和时，它只用其中一个，另外 32 字节白读了。实测（8 Mi 个点；程序本页未列出）：AoS 1.32 ms，SoA 0.44 ms，正好 3 倍；两者的读带宽都约 76 GB/s，差别全在要读的字节数上。数据布局决定了带宽里有多少是有用的。

AoS versus SoA. Storing points as struct P { float x, y, z; } p[n] is AoS (array of structures), laid out in memory as x y z x y z …; storing three arrays x[n], y[n] and z[n] is SoA (structure of arrays). One 16-byte vector load on AoS gets x0 y0 z0 x1, lanes mixing different fields, which cannot be used directly. The compiler’s answer is ld3.4s: read 48 bytes at once and de-interleave them in threes into three registers. When summing p[i].x it uses only one of them, and the other 32 bytes were read for nothing. Measured (8 Mi points; program not shown): AoS 1.32 ms, SoA 0.44 ms, exactly 3 times; both read at about 76 GB/s, and the whole difference is in how many bytes have to be read. The data layout decides how much of the bandwidth is useful.

6. Roofline：用本机实测的带宽算天花板；Accelerate 在哪里

6. The roofline: computing the ceiling from this machine’s measured bandwidth; where Accelerate fits

Roofline 模型（Williams、Waterman、Patterson，2009）用一句话说：一个循环每秒能做的浮点运算，不超过「算力上限」和「带宽 × 算术强度」两者中较小的那个。算术强度是每从内存读一个字节做几次浮点运算。点积每个元素读 8 字节（a[i] 和 b[i]），做 2 次运算（一乘一加），强度是 0.25 FLOP/B，非常低。

The roofline model (Williams, Waterman and Patterson, 2009) in one sentence: the floating-point operations a loop can do per second cannot exceed the smaller of the compute ceiling and bandwidth × arithmetic intensity. Arithmetic intensity is the number of floating-point operations per byte read from memory. A dot product reads 8 bytes per element (a[i] and b[i]) and does 2 operations (one multiply, one add), an intensity of 0.25 FLOP/B, which is very low.

  • 超出缓存（128 MB）：一个核的实测带宽约 83 GB/s（Lab A 的 neon4 82.9、vdsp 82.5 GB/s，和 Phase 0 测得的 P 簇上限一致），天花板是 0.25 × 83 ≈ 20.8 GFLOP/s。实测 20.72 和 20.62，已经贴着天花板。这时再多车道、再多累加器都没用，Accelerate 也一样，只有减少要读的字节（更小的类型、更好的布局、把几步运算合并成一遍）或者用更多的核（Phase 0：两个簇约 131 GB/s）才能更快。
  • Beyond the caches (128 MB): one core’s measured bandwidth is about 83 GB/s (Lab A’s neon4 at 82.9 and vdsp at 82.5 GB/s, matching the P-cluster ceiling measured in Phase 0), so the ceiling is 0.25 × 83 ≈ 20.8 GFLOP/s. The measured 20.72 and 20.62 are right against it. More lanes or more accumulators no longer help, and neither does Accelerate; only reading fewer bytes (a smaller type, a better layout, fusing several passes into one) or using more cores (Phase 0: about 131 GB/s with both clusters) makes it faster.
  • 放得进 L2（2 MB）：neon4 和 vdsp 都约 137 GB/s，即 34 GFLOP/s，两者一样，说明这一级也是带宽受限，只是 L2 的带宽更高。
  • Fits L2 (2 MB): neon4 and vdsp both reach about 137 GB/s, which is 34 GFLOP/s; being equal shows this level is bandwidth-bound too, only with L2’s higher bandwidth.
  • 放得进 L1（32 KB）：这里才轮到算力，写法之间差别最大：2.76、4.24、10.95、38.8–43.8、52.4 GFLOP/s。这台 M5 P 核的理论峰值 Apple 没有公开，本页不引用；52.4 只是这个循环实测到的最高值，不是硬件上限。
  • Fits L1 (32 KB): only here does compute matter, and the versions differ most: 2.76, 4.24, 10.95, 38.8–43.8 and 52.4 GFLOP/s. Apple does not publish the theoretical peak of this M5’s P core, so this page quotes none; 52.4 is only the highest value measured for this loop, not the hardware limit.

先算强度，再决定值不值得写 intrinsics：强度低于约 0.6 FLOP/B（本机 52 GFLOP/s ÷ 83 GB/s，用的是本页这个循环的实测值）、数据又大过缓存的循环，向量化只能让它更快地等内存。0.6 只是下限：52 是这个点积达到的最高值，不是核的峰值。Phase 7 实测单线程 FP32 峰值约 113 GFLOP/s、单线程带宽约 77 GB/s，脊点约 1.5 FLOP/B，并把三个内核画到这张图上。

Compute the intensity first, then decide whether intrinsics are worth writing: for a loop below about 0.6 FLOP/B (on this Mac, 52 GFLOP/s ÷ 83 GB/s, both measured for this loop on this page) whose data exceeds the caches, vectorizing only lets it wait for memory faster. Treat 0.6 as a lower bound: 52 is the best this dot product reached, not the core’s peak. Phase 7 measures a single-thread FP32 peak of about 113 GFLOP/s and single-thread bandwidth of about 77 GB/s, a ridge near 1.5 FLOP/B, and places three kernels on this chart.

Accelerate 是 macOS 自带的数值库框架，链接时加 -framework Accelerate。其中 vDSP 提供向量运算（vDSP_dotpr(a, 1, b, 1, &s, n)：两个步长为 1 的数组，结果写进 s），还有 BLAS、LAPACK、FFT 等。它由 Apple 维护，代码不公开。对标准内核，先用它，再决定要不要自己写；你自己的 neon4 在 L2 和内存尺寸上已经和它一样快，L1 上慢约 20 %。

Accelerate is the numerical framework that comes with macOS, linked with -framework Accelerate. Its vDSP part provides vector operations (vDSP_dotpr(a, 1, b, 1, &s, n): two arrays with stride 1, result written to s), alongside BLAS, LAPACK, FFTs and more. Apple maintains it, and the code is not public. For a standard kernel, use it first and then decide whether to write your own; your own neon4 is already as fast at the L2 and memory sizes, and about 20 % slower in L1.

内核一侧：向量寄存器也是线程状态的一部分。32 个 128 位 v 寄存器共 512 字节，加上 FPSR 和 FPCR，内核在上下文切换时要替线程保存、恢复它们。Linux arm64 在 arch/arm64/kernel/fpsimd.c 里用 TIF_FOREIGN_FPSTATE 标志把恢复推迟到线程返回用户态时，没用到就不搬；内核自己的代码要用 NEON，必须夹在 kernel_neon_begin() 和 kernel_neon_end() 之间。上下文切换本身见 Kernel Engineering Phase 1 · Boot & Processes。
On the kernel side: the vector registers are part of a thread’s state. The 32 128-bit v registers come to 512 bytes, plus FPSR and FPCR, and the kernel saves and restores them for the thread on a context switch. Linux arm64, in arch/arm64/kernel/fpsimd.c, uses the TIF_FOREIGN_FPSTATE flag to defer the restore until the thread returns to user space, so state that is not needed is not moved; kernel code that wants NEON itself must sit between kernel_neon_begin() and kernel_neon_end(). The context switch itself is in Kernel Engineering Phase 1 · Boot & Processes.

常见误解

Common misconceptions

  • 误解：用了 4 条车道的 SIMD，就该快 4 倍，而且到头了。→ 实际：一条累加链被乘加延迟限住，再加上独立的累加器，Lab A 在 L1 里又多得约 3.5–4 倍。
  • 误解：编译器说向量化了，循环就变快了。→ 实际：不加重排许可的 float 归约虽然报告 vectorized loop，加法仍是一条标量链，只从 2.76 升到 4.44 GFLOP/s，重排后是 43 GFLOP/s。
  • 误解：重排后的浮点结果总是更准。→ 实际：Lab A 的大点积碰巧更准，换一组数据误差方向可能相反；需要逐位可复现的结果时，要固定一种求和顺序。
  • Myth: SIMD with 4 lanes should be 4 times faster, and that is the limit. → Fact: one accumulator chain is held back by the multiply-add latency, and adding independent accumulators gave Lab A another factor of about 3.5–4 in L1.
  • Myth: if the compiler says it vectorized the loop, the loop got faster. → Fact: a float reduction without permission to reassociate reports vectorized loop yet its additions stay one scalar chain, rising only from 2.76 to 4.44 GFLOP/s, against 43 GFLOP/s once reassociated.
  • Myth: a reordered floating-point result is always more accurate. → Fact: Lab A’s large dot product happened to come out more accurate, but with other data the error can go the other way; when results must be reproducible bit for bit, fix one order of summation.

#include <Accelerate/Accelerate.h>
#include <arm_neon.h>
#include <stddef.h>

float dot_scalar(const float *a, const float *b, size_t n) {
  float s = 0.0f;
  for (size_t i = 0; i < n; ++i) s += a[i] * b[i];
  return s;
}

float dot_neon1(const float *a, const float *b, size_t n) {
  float32x4_t acc = vdupq_n_f32(0.0f);
  size_t i = 0;
  for (; i + 4 <= n; i += 4)
    acc = vfmaq_f32(acc, vld1q_f32(a + i), vld1q_f32(b + i));   // 4 条车道各做一次乘加
  float s = vaddvq_f32(acc);                                      // 横向求和：4 条车道加成 1 个数
  for (; i < n; ++i) s += a[i] * b[i];                            // 余下不足 4 个的尾巴
  return s;
}

float dot_neon4(const float *a, const float *b, size_t n) {
  float32x4_t c0 = vdupq_n_f32(0.0f), c1 = c0, c2 = c0, c3 = c0; // 4 个向量累加器 = 16 条独立的链
  size_t i = 0;
  for (; i + 16 <= n; i += 16) {
    c0 = vfmaq_f32(c0, vld1q_f32(a + i),      vld1q_f32(b + i));
    c1 = vfmaq_f32(c1, vld1q_f32(a + i + 4),  vld1q_f32(b + i + 4));
    c2 = vfmaq_f32(c2, vld1q_f32(a + i + 8),  vld1q_f32(b + i + 8));
    c3 = vfmaq_f32(c3, vld1q_f32(a + i + 12), vld1q_f32(b + i + 12));
  }
  float s = vaddvq_f32(vaddq_f32(vaddq_f32(c0, c1), vaddq_f32(c2, c3)));
  for (; i < n; ++i) s += a[i] * b[i];
  return s;
}

float dot_vdsp(const float *a, const float *b, size_t n) {
  float s;
  vDSP_dotpr(a, 1, b, 1, &s, n);                                  // Accelerate：步长 1，长度 n
  return s;
}

typedef float (*dot_fn)(const float *, const float *, size_t);

static double now_ns(void) {
  struct timespec t;
  clock_gettime(CLOCK_MONOTONIC_RAW, &t);
  return t.tv_sec * 1e9 + t.tv_nsec;
}
static int cmp(const void *x, const void *y) {
  double a = *(const double *)x, b = *(const double *)y;
  return (a > b) - (a < b);
}
volatile float sink;                                  // 结果写到这里，编译器不能删掉计算

static void bench(const char *name, dot_fn f, const float *a, const float *b, size_t n) {
  size_t inner = ((size_t)1 << 26) / n;               // 每次计时约 6400 万次乘加，小尺寸也量得准
  double t[15];
  for (int r = -1; r < 15; ++r) {                     // r = -1 是预热，不计入

    for (size_t k = 0; k < inner; ++k) sink = f(a, b, n);
    double dt = (now_ns() - t0) / inner;
    if (r >= 0) t[r] = dt;

  qsort(t, 15, sizeof t[0], cmp);
  double med = t[7];
  printf("  %-7s %10.1f ns  %5.2f GFLOP/s  %6.1f GB/s  dot=%.1f\n",
         name, med, 2.0 * n / med, 8.0 * n / med, (double)f(a, b, n));
}

}

  1. 把四个循环存成 vec.c。dot_plain 和 dot_reassoc 是同一个点积，只差一行 #pragma；find 找第一个等于 key 的元素，遇到就返回；find_blocks 做同一件事，但每 64 个一块，块内没有分支，只在块与块之间退出：Save four loops as vec.c. dot_plain and dot_reassoc are the same dot product, differing by one #pragma line; find looks for the first element equal to key and returns as soon as it sees one; find_blocks does the same in blocks of 64, with no branch inside a block, exiting only between blocks:
    // vec.c: Lab B 的四个循环。没有 main，单独编译，好读 remark 和汇编
#include <stddef.h>

float dot_plain(const float *a, const float *b, size_t n) {
  float s = 0.0f;
  for (size_t i = 0; i < n; ++i) s += a[i] * b[i];
  return s;
}

float dot_reassoc(const float *a, const float *b, size_t n) {
#pragma clang fp reassociate(on)            // 只在这个函数体里允许重排浮点加法
  float s = 0.0f;
  for (size_t i = 0; i < n; ++i) s += a[i] * b[i];
  return s;
}

int find(const int *a, size_t n, int key) {
  for (size_t i = 0; i < n; ++i)
    if (a[i] == key) return (int)i;          // 提前退出
  return -1;
}

int find_blocks(const int *a, size_t n, int key) {
  size_t i = 0;
  for (; i + 64 <= n; i += 64) {
    int hit = 0;
    for (size_t j = 0; j < 64; ++j) hit |= (a[i + j] == key);   // 块内没有分支
    if (hit) break;                          // 只在块与块之间退出
  }
  for (; i < n; ++i)
    if (a[i] == key) return (int)i;          // 在命中的那一块（或尾巴）里找准位置
  return -1;
}

#include <stdlib.h>

float dot_reassoc(const float *, const float *, size_t);

static double now_ns(void) {
  struct timespec t;
  clock_gettime(CLOCK_MONOTONIC_RAW, &t);
  return t.tv_sec * 1e9 + t.tv_nsec;
}
static int cmp(const void *x, const void *y) {
  double a = *(const double *)x, b = *(const double *)y;
  return (a > b) - (a < b);
}
volatile float fsink;
volatile int isink;

#define MEDIAN15(call, reps, out) do {                                   \
    double t_[15];                                                       \
    for (int r_ = -1; r_ < 15; ++r_) {                                   \
      double t0_ = now_ns();                                             \
      for (int k_ = 0; k_ < (reps); ++k_) call;                          \
      double dt_ = (now_ns() - t0_) / (reps);                            \
      if (r_ >= 0) t_[r_] = dt_;                                         \
    }                                                                    \
    qsort(t_, 15, sizeof t_[0], cmp);                                    \
    out = t_[7];                                                         \
  } while (0)

  float *a = malloc(n * sizeof *a), *b = malloc(n * sizeof *b);
  for (size_t i = 0; i < n; ++i) { a[i] = (float)(i % 7) * 0.25f; b[i] = (float)(i % 5) * 0.5f; }

  v[m - 1] = -7;                                  // 唯一的匹配在最后一个
  MEDIAN15(isink = find(v, m, -7), 20, t);
  printf("find         %8.0f ns  %5.1f GB/s  at=%d\n", t, 4.0 * m / t, find(v, m, -7));

  printf("find_blocks  %8.0f ns  %5.1f GB/s  at=%d\n", t, 4.0 * m / t, find_blocks(v, m, -7));
}

自测

Self-check

1. 一个 float 点积在 -O2 下报告 vectorized loop (vectorization width: 4, interleaved count: 4)，却只有 4.4 GFLOP/s，加上 #pragma clang fp reassociate(on) 后是 43 GFLOP/s，报告不变。最合理的解释是？

1. A float dot product at -O2 reports vectorized loop (vectorization width: 4, interleaved count: 4) yet runs at only 4.4 GFLOP/s; with #pragma clang fp reassociate(on) it runs at 43 GFLOP/s, and the report is unchanged. What is the most reasonable explanation?

汇编里有四条 fmul.4s，所以确实向量化了，只是加法仍是 16 条写 s0 的 fadd，关键路径没变短。两个版本用的是同一份 32 KB 数据，放得进 L1；而且带宽受限的循环不会因为一行重排许可快 10 倍。The assembly has four fmul.4s, so it was vectorized; only the additions are still 16 fadds writing s0, and the critical path did not get shorter. Both versions use the same 32 KB of data, which fits L1; and a bandwidth-bound loop would not get 10 times faster from one line of reassociation permission.

2. 数据有 128 MB 时，手写的四累加器 NEON 版本是 20.72 GFLOP/s，vDSP_dotpr 是 20.62 GFLOP/s。为什么 Accelerate 不再领先？

2. With 128 MB of data, the hand-written four-accumulator NEON version runs at 20.72 GFLOP/s and vDSP_dotpr at 20.62 GFLOP/s. Why is Accelerate no longer ahead?

两者都读到约 83 GB/s，和 roofline 算出的上限吻合，再快就要更多字节。标量代码在本机只有约 4.25 GFLOP/s，远低于 20.6，所以不是退回标量。两个程序都是单线程，没有多线程调度的问题；放到 E 核上会更慢，而不是恰好停在带宽上限。Both read at about 83 GB/s, which matches the roofline ceiling; going faster would need more bytes. Scalar code runs at only about 4.25 GFLOP/s here, far below 20.6, so it is not a scalar fallback. Both programs are single-threaded, so there is no thread scheduling at issue; an E core would be slower, not stop exactly at the bandwidth ceiling.

3. 对 8 Mi 个点的 x 求和，AoS（struct { float x, y, z; }）用 1.32 ms，SoA 用 0.44 ms，两者的读带宽都约 76 GB/s。慢在哪里？

3. Summing the x of 8 Mi points takes 1.32 ms with AoS (struct { float x, y, z; }) and 0.44 ms with SoA, and both read at about 76 GB/s. Where does the time go?

带宽一样，时间正好 3 倍，差别只能在字节数上：ld3.4s 读 48 字节只用 16 字节。概念 5 测过，未对齐的 vld1q_f32 在 L1 里没有差别，在 L2 里只差约 1.7 %，解释不了 3 倍。AoS 循环报告了 vectorized loop，汇编里是 ld3.4s 和 fadd.4s，并没有退回标量。The bandwidth is the same and the time is exactly 3 times, so the difference can only be in the bytes: ld3.4s reads 48 bytes and uses 16. Concept 5 measured that an unaligned vld1q_f32 makes no difference in L1 and only about 1.7 % in L2, which cannot explain 3 times. The AoS loop reported vectorized loop, and its assembly has ld3.4s and fadd.4s; it did not fall back to scalar.

4. for (i = 0; i < n; ++i) if (a[i] == key) return i; 的报告是 Cannot vectorize potentially faulting early exit loop。哪个改动能让它向量化？

4. The report for for (i = 0; i < n; ++i) if (a[i] == key) return i; is Cannot vectorize potentially faulting early exit loop. Which change lets it vectorize?

问题在于提前退出后，向量版本可能已经读过数组末尾。分块后块内的 64 次读取无论如何都会发生，Lab B 里这个内层循环报告向量化，快了 6.3 倍。-ffast-math 只放宽浮点语义，这里是整数比较；restrict 处理的是指针重叠，这个循环只读一个数组。The problem is that after an early exit the vector version might already have read past the end of the array. With blocks, all 64 reads in a block happen in any case; in Lab B this inner loop reports vectorized and runs 6.3 times faster. -ffast-math only relaxes floating-point semantics, and this is an integer comparison; restrict deals with overlapping pointers, and this loop reads only one array.
