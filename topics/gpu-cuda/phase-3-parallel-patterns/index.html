The last three lessons were about how a GPU runs a kernel; this one is about the few shapes most kernels take. A reduction folds n values into one, a scan gives every position the sum of what came before it, a histogram has many threads adding into a few bins, a stencil has every output read a ring of neighbours, and a radix sort is a histogram plus a scan, repeated. Each has a naive form and a good form, and the difference always comes down to the same tools: shared memory, __syncthreads(), warp shuffles and atomics. Last, we see how Thrust and CUB wrap these forms into a single call. 核心概念

Core concepts

求和、前缀和、直方图看上去都排斥并行：求和是一条 n − 1 次加法的链，前缀和的每个输出都依赖前一个，直方图里任意两个线程随时可能撞上同一个格子。几千个线程要是排在一条依赖链上，或者挤在同一个地址上排队，GPU 就和一个核没有区别。机制要做到两件事：把依赖链改写成只有 log₂ n 层的树，而总工作量不明显变多；把同步和争用放在最便宜的地方，也就是寄存器和 shared memory，而不是全 block 的屏障和全局原子操作。

A sum, a prefix sum and a histogram all look hostile to parallelism: a sum is a chain of n − 1 additions, every output of a prefix sum depends on the one before, and in a histogram any two threads may hit the same bin at any moment. If thousands of threads line up on one dependency chain or queue on one address, the GPU is no better than a single core. The mechanism has to achieve two things: rewrite the chain as a tree only log₂ n levels deep without much more total work, and keep synchronization and contention in the cheapest place, registers and shared memory, rather than whole-block barriers and global atomics.

概念 1 的树形归约加 warp shuffle 和概念 2 的 Blelloch 扫描回答前一件，概念 3 的私有化回答后一件。

The tree reduction with warp shuffles of concept 1 and the Blelloch scan of concept 2 answer the first; privatization in concept 3 answers the second.

1. 归约：从 shared memory 里的树到 warp shuffle

1. Reduction: from a tree in shared memory to warp shuffles

归约用一个满足结合律的运算（加法、最大值、按位或）把 n 个数合成一个。串行要 n − 1 次运算、n − 1 步；并行时两两相加，每一层数量减半，工作量还是 n − 1 次，跨度降到 log₂ n 层。在一个 block 里，最直接的写法是把每个线程的值放进 shared memory，然后一层一层地加：

A reduction folds n values into one with an associative operator (addition, maximum, bitwise or). Sequentially that is n − 1 operations in n − 1 steps; in parallel, values are added in pairs and halve at each level, so the work is still n − 1 operations but the span drops to log₂ n levels. Inside a block, the direct way is to put each thread’s value in shared memory and add level by level:

  • 顺序寻址。第 k 层让线程 t < k 做 s[t] += s[t + k]，k 从 BLOCK / 2 开始减半。活跃的线程总是连在一起的前 k 个，所以退出的是整个 warp，而不是在一个 warp 里一半干活一半空等（Phase 2 的分叉）。另一种写法让线程 2kt 去加，活跃线程隔一个用一个，每个 warp 都在分叉，这是 PMPP 第 10 章用来讲「减少分叉」的例子。
  • Sequential addressing. At level k, threads t < k do s[t] += s[t + k], with k halving from BLOCK / 2. The active threads are always the first k in a row, so whole warps retire instead of half a warp working while the other half waits (Phase 2’s divergence). The other form has thread 2kt do the adding, so every other thread is active and every warp diverges; chapter 10 of PMPP uses it as its example of reducing divergence.
  • 每层一个 __syncthreads()。下一层要读上一层别的线程写的值，所以每层之间都要一次全 block 的屏障。256 个线程是 8 层、8 次屏障。
  • One __syncthreads() per level. Each level reads values that other threads wrote in the level before, so every level needs a barrier for the whole block. For 256 threads that is 8 levels and 8 barriers.

问题出在最后几层。k 降到 16 及以下时（k = 16、8、4、2、1，正好 5 层），活跃的线程全在第一个 warp 里，读的也只是这个 warp 自己写的值，剩下 7 个 warp 只是陪着过屏障；每一层还要把值写进 shared memory 再读出来。warp shuffle 让一个 warp 的 lane 直接读彼此的寄存器。CUDA Programming Guide 5.4.6.5 给出的签名是：

The trouble is in the last few levels. Once k is 16 or less (k = 16, 8, 4, 2, 1, exactly 5 levels), every active thread is in the first warp and reads only values that warp wrote, while the other 7 warps only come along for the barriers; and each level still writes its values to shared memory and reads them back. A warp shuffle lets the lanes of a warp read each other’s registers directly. Section 5.4.6.5 of the CUDA Programming Guide gives the signature:

T __shfl_down_sync(unsigned mask, T value, unsigned delta, int width=warpSize);
  • 它返回什么。调用者拿到 lane 号为「自己的 lane 号 + delta」的那个线程手里的 value。源超出 warp 时不回绕，最上面 delta 个 lane 拿回的是自己的值。所以 v += __shfl_down_sync(0xffffffff, v, d) 在 d = 16、8、4、2、1 上走 5 轮，lane 0 就拿到整个 warp 的和，其余 lane 的结果不用管。
  • What it returns. The caller gets the value held by the lane whose ID is its own lane ID plus delta. The source does not wrap past the warp, so the top delta lanes get their own values back. So v += __shfl_down_sync(0xffffffff, v, d) over d = 16, 8, 4, 2, 1 takes 5 rounds and leaves the sum of the whole warp in lane 0; the other lanes’ results do not matter.
  • 掩码承诺了什么。mask 的每一位对应一个 lane。指南 5.4.6.6 写明：这个内建函数会等掩码里所有没退出的 lane 都到达这次调用；掩码里点名的 lane 必须都执行同一个调用，否则行为未定义。全掩码 0xffffffff 就是承诺 32 个 lane 都会走到这里。所以越界的线程不能提前 return，而是带着 0 一起参加 shuffle，Lab A 的 kernel 正是这样写的。
  • What the mask promises. Each bit of mask stands for one lane. Section 5.4.6.6 of the guide states that the intrinsic waits until every non-exited lane in the mask reaches the call, and that the lanes the mask names must all execute the same call, or the behaviour is undefined. The full mask 0xffffffff promises that all 32 lanes get there. So out-of-range threads must not return early; they join the shuffle carrying 0, and the Lab A kernels are written that way.
  • 为什么不需要 __syncthreads()。交换发生在同一个 warp 的寄存器之间，shuffle 本身就让掩码里的 lane 在这一点汇合。不能退回老写法，即省掉同步、靠「一个 warp 总是齐步走」去读 shared memory：从 Volta 起有独立线程调度，同一个 warp 的 lane 不保证齐步执行（Phase 2）。
  • Why no __syncthreads() is needed. The exchange happens between registers of one warp, and the shuffle itself brings the lanes of the mask together at that point. Do not fall back on the old trick of dropping synchronization and reading shared memory on the belief that a warp always runs in step: since Volta, with independent thread scheduling, the lanes of a warp are not guaranteed to run in step (Phase 2).

于是 block 级的归约变成两段：每个 warp 用 5 轮 shuffle 得到自己的和，lane 0 写进 partial[warp]；一次 __syncthreads()；warp 0 读回 8 个部分和，再 shuffle 一轮，lane 0 做一次 atomicAdd。屏障从 9 次（装入后一次，加上每层一次）降到 1 次。再进一步是线程粗化：每个线程先在寄存器里按 grid 跨步累加很多个元素，再做一次上面的归约，block 数和原子操作都少得多（Lab A 的 reduce_shfl_coarse）。还有一个现成的函数 __reduce_add_sync(mask, value) 一次做完 warp 内的整数求和，但指南 5.4.6.4 写明它要 compute capability 8.x 或更高，T4（sm_75）上没有，所以本课不用它。

So the block-level reduction has two parts: each warp gets its own sum in 5 rounds of shuffles and lane 0 writes it to partial[warp]; one __syncthreads(); warp 0 reads back the 8 partial sums, shuffles once more, and lane 0 does one atomicAdd. Barriers drop from 9 (one after loading plus one per level) to 1. One step further is thread coarsening: each thread first adds many elements in registers, striding over the grid, and then does the reduction above, which needs far fewer blocks and atomics (reduce_shfl_coarse in Lab A). There is also a ready-made __reduce_add_sync(mask, value) that does a warp’s integer sum in one call, but section 5.4.6.4 of the guide says it needs compute capability 8.x or higher; the T4 (sm_75) lacks it, so this lesson does not use it.

2. 扫描：Hillis–Steele 与 Blelloch

2. Scan: Hillis–Steele and Blelloch

扫描（scan，也叫前缀和）给每个位置算出它之前的累计值。包含扫描的第 i 个输出是 x₀ 到 xᵢ 的和，排他扫描是 x₀ 到 xᵢ₋₁ 的和，第一个输出是 0。串行只要 n − 1 次加法，但每一步都依赖上一步，看起来没法并行。两种经典的并行写法用不同的代价换掉了这条依赖链：

A scan, or prefix sum, gives every position the running total of what came before it. Output i of an inclusive scan is the sum of x₀ to xᵢ; an exclusive scan sums x₀ to xᵢ₋₁, so its first output is 0. Sequentially that takes only n − 1 additions, but each step depends on the one before, so it looks impossible to parallelize. The two classic parallel forms trade that chain away at different costs:

  • Hillis–Steele（包含扫描）。做 log₂ n 轮，第 d 轮（d = 1、2、4、…）每个 t ≥ d 的元素都加上 t − d 的元素。跨度只有 log₂ n 层，但每一轮几乎所有元素都在做加法：总共 (n − 1) + (n − 2) + (n − 4) + … = n log₂ n − (n − 1) 次。n = 1024 时是 9217 次，而串行只要 1023 次。这就是 O(n log n) 的工作量，它不是工作高效的（work-efficient）。同一轮里读和写会碰到同一个位置，所以要双缓冲。
  • Hillis–Steele (inclusive). It runs log₂ n rounds; in round d (d = 1, 2, 4, …) every element t ≥ d adds element t − d. The span is only log₂ n levels, but in every round nearly every element does an addition: (n − 1) + (n − 2) + (n − 4) + … = n log₂ n − (n − 1) in all. At n = 1024 that is 9217 additions, where the sequential scan needs 1023. That is O(n log n) work: the algorithm is not work-efficient. Reads and writes of one round touch the same positions, so it needs double buffering.
  • Blelloch（排他扫描）。先上扫：就是一棵原地的归约树，n − 1 次加法，根上留下总和。把根换成 0。再下扫：从根往下，每个节点把自己的值交给左孩子，把「自己的值加左孩子原来的值」交给右孩子，又是 n − 1 次加法。合计 2(n − 1) 次，n = 1024 时 2046 次，和串行同阶，是 O(n) 的工作量；代价是 2 log₂ n 层，层数是 Hillis–Steele 的两倍。图解 (b) 一步一步演示了这个过程。
  • Blelloch (exclusive). First the up-sweep: an in-place reduction tree, n − 1 additions, leaving the total at the root. The root is replaced by 0. Then the down-sweep: from the root down, every node hands its value to its left child and its value plus the left child’s old value to its right child, another n − 1 additions. That is 2(n − 1) in all, 2046 at n = 1024, the same order as the sequential scan, O(n) work; the price is 2 log₂ n levels, twice as many as Hillis–Steele. Diagram (b) walks through it step by step.

  2. d = 2: positions 2 to 7 each add the value two places back, 6 additions. Every position now holds itself plus up to three values before it; the 11 at position 3 is 3 + 1 + 7 + 0.

  4. That is 7 + 6 + 4 = 17 additions, against 14 for Blelloch and 7 sequentially, in 3 levels against 6. Shift it right by one with a 0 in front and it is the exclusive result of diagram (b), 0 3 4 11 11 15 16 22. At n = 1024 the same count is 9217 against 2046.

哪个更好取决于线程够不够多。元素比线程多很多时，多出来的加法要占真实的执行时间，工作高效的 Blelloch 赢；元素数不超过并行宽度时（比如一个 warp 的 32 个数），多做的加法反正有空闲 lane 来做，层数少的 Hillis–Steele 更快（推断：这是常见的取舍，本页没有测）。这也是 warp 内的扫描常用 __shfl_up_sync 按 Hillis–Steele 的方式写的原因（推断）。Metal 直接提供了 SIMD-group 级的 simd_prefix_exclusive_sum 和 simd_prefix_inclusive_sum（规范 6.10.2）。

Which is better depends on whether there are enough threads. With many more elements than threads, the extra additions cost real execution time and the work-efficient Blelloch wins; when the elements fit in the parallel width (the 32 values of a warp, say), the extra additions run on lanes that would idle anyway, and Hillis–Steele with fewer levels is faster (inference: this is the common trade-off; this page did not measure it). That is also why scans inside a warp are usually written Hillis–Steele style with __shfl_up_sync (inference). Metal provides SIMD-group scans directly as simd_prefix_exclusive_sum and simd_prefix_inclusive_sum (specification 6.10.2).

两点补充。第一，一个 block 只能扫描它装得下的数据；大数组要分层：每个 block 扫描自己的一段并输出段和，再扫描这些段和，最后把结果加回每一段。PMPP 第 11 章讲的就是这种分层扫描。第二，Blelloch 的上扫和下扫按 2 的幂的步长访问 shared memory，会碰到 Phase 1 的 bank 冲突；GPU Gems 3 第 39 章用补位消除它们。

Two more points. First, one block can only scan what it holds; a large array is scanned in layers: each block scans its own segment and outputs the segment total, the totals are scanned, and the results are added back to each segment. Chapter 11 of PMPP covers this hierarchical scan. Second, the up-sweep and down-sweep of Blelloch access shared memory at power-of-two strides and run into the bank conflicts of Phase 1; chapter 39 of GPU Gems 3 removes them with padding.

基数排序（概要）。扫描最重要的用途之一是排序。基数排序每一趟看键的 b 位：先数每个桶有几个元素（一个直方图），再对这些计数做排他扫描，扫描结果就是每个桶在输出里的起点，最后每个元素按「桶起点 + 在桶里的序号」稳定地写到新位置。k 位的键要 k / b 趟，每趟 O(n)。CUB 的 cub::DeviceRadixSort::SortKeys 就是它的现成版本，CCCL 文档写明它需要约 2N 的辅助存储，并可以用 begin_bit、end_bit 只排一部分位。

Radix sort, in outline. One of the most important uses of scan is sorting. Each pass of a radix sort looks at b bits of the key: it counts how many elements fall in each bucket (a histogram), takes the exclusive scan of those counts, which gives each bucket its starting position in the output, and writes every element stably to that start plus its rank within the bucket. Keys of k bits need k / b passes, each O(n). CUB’s cub::DeviceRadixSort::SortKeys is the ready-made form; the CCCL documentation says it needs about 2N of auxiliary storage and can sort on part of the key with begin_bit and end_bit.

3. 直方图：原子操作与私有化

3. Histogram: atomics and privatization

直方图让每个输入把某个格子（bin）加一。哪个格子由数据决定，所以两个线程随时可能撞上同一个格子，必须用原子操作。指南 5.4.5.1 对 atomicAdd() 的描述是：读出 global 或 shared memory 里的一个字，加上一个数，再写回同一个地址，整个读改写不可分割；这些函数的内存顺序是 memory_order_relaxed，只保证原子性，不排序别的访问。

A histogram has every input add one to some bin. The data decides which bin, so two threads can hit the same bin at any moment, and the update must be atomic. Section 5.4.5.1 of the guide describes atomicAdd() as reading a word in global or shared memory, adding a number and writing it back to the same address, with the whole read-modify-write indivisible; these functions have memory_order_relaxed ordering, which guarantees atomicity and orders no other accesses.

朴素版让每个元素直接对全局的 bins[v] 做一次 atomicAdd。对同一个地址的原子操作只能一个接一个地完成，数据越偏（比如一段英文里的空格和字母 e），撞在热门格子上的线程越多，排队越长。私有化（privatization）给每个 block 一份自己的直方图，放在 shared memory 里：

The naive version has every element do one atomicAdd on the global bins[v]. Atomics on one address can only complete one after another, and the more skewed the data (the spaces and the letter e in English text, say), the more threads pile onto the popular bins and the longer the queue. Privatization gives each block a histogram of its own, in shared memory:

  1. 清零：block 的线程一起把 local[BINS] 置 0，然后 __syncthreads()。
  2. Clear: the threads of the block zero local[BINS] together, then __syncthreads().
  3. 计数：每个线程对 local 做 atomicAdd。这仍是原子操作，但在片上，而且只和本 block 的线程争。
  4. Count: each thread does its atomicAdd on local. These are still atomics, but on chip, and contended only by the threads of this block.
  5. 合并：再一次 __syncthreads()，然后每个 bin 由一个线程把 local[b] 一次加到全局的 bins[b]。
  6. Merge: one more __syncthreads(), then one thread per bin adds local[b] to the global bins[b] in a single atomic.

全局原子操作因此从 n 次降到「block 数 × BINS」次以内。配合线程粗化（grid 跨步循环，block 数只取 SM 数的几倍），这个数还会更小。代价是每个 block 要清零和合并 BINS 个格子，并占 BINS × 4 字节的 shared memory：256 个 bin 是 1 KB，对占用率几乎没有影响；几万个 bin 的直方图放不进 shared memory，私有化就要换别的办法。

Global atomics therefore drop from n to at most the number of blocks times BINS. With thread coarsening (a grid-stride loop, and only a few blocks per SM), the number falls further. The price is that each block clears and merges BINS bins and holds BINS × 4 bytes of shared memory: 256 bins is 1 KB, which barely touches occupancy, while a histogram of tens of thousands of bins does not fit in shared memory and needs another approach to privatization.

// 未运行 · not run; assembled from the CUDA documentation on 2026-10-31
// 私有化直方图：每个 block 先在 shared memory 里计数，最后每个 bin 只做一次全局 atomicAdd
#define BINS 256
__global__ void histo_private(const unsigned char* data, unsigned* bins, int n) {
    __shared__ unsigned local[BINS];
    for (int b = threadIdx.x; b < BINS; b += blockDim.x) local[b] = 0;
    __syncthreads();
    for (int i = blockIdx.x * blockDim.x + threadIdx.x; i < n; i += gridDim.x * blockDim.x)
        atomicAdd(&local[data[i]], 1u);          // 片上的原子操作，只和本 block 的线程争
    __syncthreads();
    for (int b = threadIdx.x; b < BINS; b += blockDim.x)
        if (local[b]) atomicAdd(&bins[b], local[b]);   // 合并：每个 block 每个 bin 至多一次
}

4. 模板计算与光环的代价

4. Stencils and what the halo costs

模板计算（stencil）让每个输出由它周围半径 R 内的输入按固定的权重算出：一维的三点平滑、二维的五点拉普拉斯、三维的七点热传导都是。每个输入被它的好几个邻居输出重复读取，所以和 Phase 1 的矩阵乘一样，要把一块数据搬进 shared memory 复用。不同之处在边上：一个 block 要算 T × T 个输出，就得装入 (T + 2R) × (T + 2R) 个输入，多出来的那一圈叫光环（halo），它们属于相邻的块，被两个 block 各读一次。

A stencil computes each output from the inputs within radius R around it, with fixed weights: a three-point smoothing in one dimension, a five-point Laplacian in two, a seven-point heat equation in three. Each input is read again by several neighbouring outputs, so as with the matrix multiply of Phase 1 a tile of data goes into shared memory for reuse. The difference is at the edge: to compute T × T outputs a block has to load (T + 2R) × (T + 2R) inputs, and the extra ring is the halo; those cells belong to neighbouring tiles and are read once by each of the two blocks.

  • 光环的比例。d 维、边长 T、半径 R 时，装入量和输出量之比是 ((T + 2R) / T)d。一维 T = 256、R = 1：258 / 256，多读不到 1%。二维 3 × 3 模板、T = 16：18² = 324 对 256，多读 27%。三维七点模板、T = 8：10³ = 1000 对 512，几乎多读一倍。
  • The halo ratio. In d dimensions with tile side T and radius R, inputs loaded per output are ((T + 2R) / T)d. In one dimension with T = 256 and R = 1: 258 / 256, under 1% extra. A 3 × 3 stencil in two dimensions with T = 16: 18² = 324 against 256, 27% extra. A seven-point stencil in three dimensions with T = 8: 10³ = 1000 against 512, nearly double.
  • 为什么三维这么贵。T 越大光环占比越小，但 T 受两个上限约束：一个 block 最多 1024 个线程，三维里 T = 8 时一个线程一个输入已经是 10³ = 1000 个线程；shared memory 也有限。常见的办法是只在 shared memory 里放一个二维切片，沿 z 方向一层一层推进，z 方向的邻居放在寄存器里（推断：这是常见做法，PMPP 第 8 章按章名对应，本页没有核对它的具体写法）。
  • Why three dimensions cost so much. A larger T shrinks the halo share, but T has two ceilings: a block has at most 1024 threads, and with T = 8 in three dimensions one thread per input is already 10³ = 1000 threads; shared memory is limited too. The usual fix keeps only a two-dimensional slice in shared memory, marches along z one layer at a time, and holds the z neighbours in registers (inference: this is the common approach, matched to chapter 8 of PMPP by its title; this page has not checked the book’s exact form).
  • 谁来装光环。一种做法让 block 的线程数等于输入块的大小，外圈的线程只装数据、不算输出，空闲的比例正好就是上面多出来的那部分；另一种让线程数等于输出块，部分线程多装一个光环元素，代码更复杂但没有空闲线程。网格本身的边界还要处理越界的「幽灵格」（ghost cells），通常按边界条件补 0 或复制边上的值。
  • Who loads the halo. One way makes the block as large as the input tile, so the outer threads only load and compute no output, and the idle share is exactly the extra fraction above; the other makes the block as large as the output tile, with some threads loading one halo element extra, which is more complex code but leaves no thread idle. The edge of the grid itself also needs ghost cells for out-of-range neighbours, usually filled with 0 or a copy of the edge value according to the boundary condition.

模板的权重对所有线程都一样，正适合 Phase 1 的 constant memory：一个 warp 读同一个系数，是广播。

The stencil weights are the same for every thread, which suits Phase 1’s constant memory: a warp reading one coefficient is a broadcast.

  • A reduction turns a chain of n − 1 additions into a tree log₂ n levels deep with the same work, and sequential addressing retires whole warps rather than half of each.
  • The last 5 levels go to __shfl_down_sync, passing values between the registers of one warp, so block barriers drop from 9 to 1 and global atomics to one per block.
  • The shuffle mask is a promise that every lane it names reaches the call, so out-of-range threads join carrying 0 instead of returning early.
  • Hillis–Steele has fewer levels but makes n log₂ n − (n − 1) additions, while Blelloch makes only 2(n − 1) in twice the levels; with many more elements than threads Blelloch wins.
  • Privatization has each block count in shared memory first, so global atomics drop from n to at most the number of blocks times BINS.

常见误解

Common misconceptions

  • 误解：一个 warp 总是齐步执行，所以 warp 内读 shared memory 可以省掉同步。→ 实际：从 Volta 起有独立线程调度，lane 不保证齐步，要用带掩码的 shuffle 或显式同步。
  • 误解：层数最少的扫描就是最快的扫描。→ 实际：Hillis–Steele 在 n = 1024 时做 9217 次加法，Blelloch 只做 2046 次；只有元素不超过并行宽度时，多做的加法才不花时间。
  • 误解：每个元素一次全局 atomicAdd 一定慢得没法用。→ 实际：NVIDIA 的博客写明 nvcc 在很多情况下会自动把一个 warp 对同一地址的原子操作合成一次，要量过才知道。
  • Myth: a warp always runs in step, so reads of shared memory inside a warp need no synchronization. → Fact: since Volta, with independent thread scheduling, lanes are not guaranteed to run in step; use a masked shuffle or explicit synchronization.
  • Myth: the scan with the fewest levels is the fastest scan. → Fact: at n = 1024 Hillis–Steele makes 9217 additions and Blelloch 2046; the extra additions cost nothing only when the elements fit in the parallel width.
  • Myth: one global atomicAdd per element is always hopelessly slow. → Fact: NVIDIA’s blog states that nvcc in many cases combines a warp’s atomics on one address into one automatically, so it has to be measured.

// reduce.cu: 求和归约，从朴素原子加到 warp shuffle，最后和 cub::DeviceReduce::Sum 比较
#include <algorithm>
#include <cstdio>
#include <cstdlib>
#include <vector>
#include <cuda_runtime.h>
#include <cub/cub.cuh>

#define CHECK(call) do { cudaError_t e_ = (call); if (e_ != cudaSuccess) { \
    std::fprintf(stderr, "%s:%d %s\n", __FILE__, __LINE__, cudaGetErrorString(e_)); std::exit(1); } } while (0)
#define BLOCK 256
#define FULL 0xffffffffu   // 全掩码：warp 的 32 个 lane 都参加

// 0. 朴素：每个线程对同一个全局计数器 atomicAdd 一次
__global__ void reduce_atomic(const unsigned* in, unsigned* out, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) atomicAdd(out, in[i]);
}

// 1. 树形归约：8 层全在 shared memory 里，每层一个 __syncthreads；每个 block 一次 atomicAdd
__global__ void reduce_tree(const unsigned* in, unsigned* out, int n) {
    __shared__ unsigned s[BLOCK];
    int t = threadIdx.x, i = blockIdx.x * BLOCK + t;
    s[t] = (i < n) ? in[i] : 0;
    __syncthreads();
    for (int k = BLOCK / 2; k > 0; k >>= 1) {    // 顺序寻址：活跃线程连在一起，整 warp 退出而不分叉
        if (t < k) s[t] += s[t + k];
        __syncthreads();
    }
    if (t == 0) atomicAdd(out, s[0]);
}

// warp 内的 5 层：值在寄存器之间直接传，不经过 shared memory，也不需要 __syncthreads
__device__ unsigned warp_sum(unsigned v) {
    for (int d = 16; d > 0; d >>= 1) v += __shfl_down_sync(FULL, v, d);
    return v;                                    // lane 0 拿到整个 warp 的和
}

// 2. shuffle：每个 warp 先自己归约，shared memory 只用来交换 8 个 warp 的部分和
__global__ void reduce_shfl(const unsigned* in, unsigned* out, int n) {
    __shared__ unsigned partial[BLOCK / 32];
    int t = threadIdx.x, i = blockIdx.x * BLOCK + t, lane = t % 32, warp = t / 32;
    unsigned v = warp_sum((i < n) ? in[i] : 0);  // 越界线程贡献 0，但照样参加 shuffle
    if (lane == 0) partial[warp] = v;
    __syncthreads();
    if (warp == 0) {
        v = warp_sum((lane < BLOCK / 32) ? partial[lane] : 0);
        if (lane == 0) atomicAdd(out, v);
    }
}

// 3. 线程粗化：每个线程先按 grid 跨步累加很多个元素，再做一次 shuffle 归约，block 数少得多
__global__ void reduce_shfl_coarse(const unsigned* in, unsigned* out, int n) {
    __shared__ unsigned partial[BLOCK / 32];
    int t = threadIdx.x, lane = t % 32, warp = t / 32;
    unsigned v = 0;
    for (int i = blockIdx.x * BLOCK + t; i < n; i += gridDim.x * BLOCK) v += in[i];
    v = warp_sum(v);
    if (lane == 0) partial[warp] = v;
    __syncthreads();
    if (warp == 0) {
        v = warp_sum((lane < BLOCK / 32) ? partial[lane] : 0);
        if (lane == 0) atomicAdd(out, v);
    }
}

        CHECK(cudaGetLastError());

        CHECK(cudaEventSynchronize(t1));

    CHECK(cudaEventDestroy(t0)); CHECK(cudaEventDestroy(t1));
    std::sort(ms.begin(), ms.end());
    return ms[ms.size() / 2];
}

// 未运行 · not run; assembled from the CUDA documentation on 2026-10-31
// scan.cu: 一个 block 内的两种扫描（Hillis–Steele 与 Blelloch），数出各自做了几次加法；再用 Thrust 扫描 2^24 个数
#include <cstdio>
#include <cstdlib>
#include <vector>
#include <cuda_runtime.h>
#include <thrust/device_vector.h>
#include <thrust/scan.h>

#define CHECK(call) do { cudaError_t e_ = (call); if (e_ != cudaSuccess) { \
    std::fprintf(stderr, "%s:%d %s\n", __FILE__, __LINE__, cudaGetErrorString(e_)); std::exit(1); } } while (0)
#define N 1024

// Hillis–Steele 包含扫描：N 个线程，log2(N) 轮，每轮几乎所有线程都做一次加法；双缓冲避免读写同一格
__global__ void scan_hillis_steele(const unsigned* in, unsigned* out, unsigned* adds) {
    __shared__ unsigned buf[2][N];
    int t = threadIdx.x, p = 0;
    buf[0][t] = in[t];
    __syncthreads();
    for (int d = 1; d < N; d <<= 1) {
        if (t >= d) { buf[1 - p][t] = buf[p][t] + buf[p][t - d]; atomicAdd(adds, 1u); }
        else buf[1 - p][t] = buf[p][t];
        p = 1 - p;
        __syncthreads();
    }
    out[t] = buf[p][t];
}

// Blelloch 排他扫描：N / 2 个线程，每个管两个元素；上扫建部分和的树，下扫把前缀分发回去
__global__ void scan_blelloch(const unsigned* in, unsigned* out, unsigned* adds) {
    __shared__ unsigned s[N];
    int t = threadIdx.x, off = 1;
    s[2 * t] = in[2 * t]; s[2 * t + 1] = in[2 * t + 1];
    for (int d = N / 2; d > 0; d >>= 1) {        // 上扫：每层活跃线程减半
        __syncthreads();
        if (t < d) {
            int a = off * (2 * t + 1) - 1, b = off * (2 * t + 2) - 1;
            s[b] += s[a]; atomicAdd(adds, 1u);
        }
        off <<= 1;
    }
    if (t == 0) s[N - 1] = 0;                    // 根清零：排他扫描的单位元
    for (int d = 1; d < N; d <<= 1) {            // 下扫：每层活跃线程加倍
        off >>= 1;
        __syncthreads();
        if (t < d) {
            int a = off * (2 * t + 1) - 1, b = off * (2 * t + 2) - 1;
            unsigned x = s[a]; s[a] = s[b]; s[b] += x; atomicAdd(adds, 1u);
        }
    }
    __syncthreads();
    out[2 * t] = s[2 * t]; out[2 * t + 1] = s[2 * t + 1];
}

int main() {
    std::vector<unsigned> h(N), inc(N), exc(N), got(N);
    for (int i = 0; i < N; ++i) h[i] = i % 13;
    unsigned run = 0;
    for (int i = 0; i < N; ++i) { exc[i] = run; run += h[i]; inc[i] = run; }   // CPU 参考结果

    unsigned *in, *out, *adds;
    CHECK(cudaMalloc(&in, N * sizeof(unsigned))); CHECK(cudaMalloc(&out, N * sizeof(unsigned)));
    CHECK(cudaMalloc(&adds, sizeof(unsigned)));
    CHECK(cudaMemcpy(in, h.data(), N * sizeof(unsigned), cudaMemcpyHostToDevice));

    for (int k = 0; k < 2; ++k) {
        CHECK(cudaMemset(adds, 0, sizeof(unsigned)));
        if (k == 0) scan_hillis_steele<<<1, N>>>(in, out, adds);
        else        scan_blelloch<<<1, N / 2>>>(in, out, adds);
        CHECK(cudaGetLastError());
        CHECK(cudaDeviceSynchronize());
        unsigned a = 0;
        CHECK(cudaMemcpy(&a, adds, sizeof(unsigned), cudaMemcpyDeviceToHost));
        CHECK(cudaMemcpy(got.data(), out, N * sizeof(unsigned), cudaMemcpyDeviceToHost));
        const std::vector<unsigned>& ref = (k == 0) ? inc : exc;
        int bad = 0;
        for (int i = 0; i < N; ++i) bad += got[i] != ref[i];
        std::printf("%-14s n=%d  additions %u  mismatches %d\n", k == 0 ? "hillis_steele" : "blelloch", N, a, bad);
    }

    // 库的写法：Thrust 对 2^24 个元素做排他扫描，结果和 CPU 比较
    const int M = 1 << 24;
    std::vector<unsigned> hm(M);
    for (int i = 0; i < M; ++i) hm[i] = i % 13;
    thrust::device_vector<unsigned> d_in(hm.begin(), hm.end()), d_out(M);
    cudaEvent_t t0, t1;
    CHECK(cudaEventCreate(&t0)); CHECK(cudaEventCreate(&t1));
    thrust::exclusive_scan(d_in.begin(), d_in.end(), d_out.begin());   // 预热
    CHECK(cudaEventRecord(t0));
    thrust::exclusive_scan(d_in.begin(), d_in.end(), d_out.begin());
    CHECK(cudaEventRecord(t1));
    CHECK(cudaEventSynchronize(t1));
    float ms = 0; CHECK(cudaEventElapsedTime(&ms, t0, t1));
    std::vector<unsigned> hout(M);
    thrust::copy(d_out.begin(), d_out.end(), hout.begin());
    unsigned r = 0; int bad = 0;
    for (int i = 0; i < M; ++i) { bad += hout[i] != r; r += hm[i]; }
    std::printf("thrust::exclusive_scan n=2^24  %.3f ms  mismatches %d\n", ms, bad);
    CHECK(cudaEventDestroy(t0)); CHECK(cudaEventDestroy(t1));
    CHECK(cudaFree(in)); CHECK(cudaFree(out)); CHECK(cudaFree(adds));
    return 0;
}

using namespace metal;
#define TG 1024   // 每个 threadgroup 的线程数，Swift 端派发时用同一个值

// 朴素：每个线程对同一个全局计数器做一次原子加
kernel void reduce_atomic(device const uint* in  [[buffer(0)]],
                          device atomic_uint* out [[buffer(1)]],
                          uint i [[thread_position_in_grid]]) {
    atomic_fetch_add_explicit(out, in[i], memory_order_relaxed);
}

// 同样是每个线程一次原子加，但地址取决于读到的数据（值都小于 13，所以其实总是 out[0]），
// 编译器无法在编译时断定一个 SIMD-group 的地址相同

                                 uint i [[thread_position_in_grid]]) {
    uint v = in[i];

}

// 树形归约：全部 10 层都在 threadgroup 内存里做，每层一个屏障；每个 threadgroup 一次原子加

Self-check

1. 归约的最后 5 层改用 __shfl_down_sync(0xffffffff, v, d) 后，层与层之间为什么不再需要 __syncthreads()？

1. Once the last 5 levels of a reduction use __shfl_down_sync(0xffffffff, v, d), why is no __syncthreads() needed between levels?

shuffle 只在一个 warp 内交换寄存器，指南写明它会等掩码里所有没退出的 lane 到达这次调用，所以同步由它自己完成，跨 warp 的 block 屏障就多余了。「warp 总是齐步走」正是 Volta 以后不再成立的老假设，独立线程调度下 lane 可以各走各的。最后几层也不是只剩 lane 0：d = 16 时有 16 个 lane 在加，而且每一轮所有 32 个 lane 都必须参加 shuffle。A shuffle exchanges registers within one warp only, and the guide states that it waits until every non-exited lane in the mask reaches the call, so it does its own synchronization and a block-wide barrier is redundant. That a warp always runs in step is exactly the old assumption that stopped holding after Volta: with independent thread scheduling the lanes may go their own ways. Nor is lane 0 alone in the last levels: at d = 16, 16 lanes are adding, and all 32 lanes must take part in every round of the shuffle.

2. 对 1024 个数做扫描，Hillis–Steele 和 Blelloch 各是什么情况？

2. Scanning 1024 values, how do Hillis–Steele and Blelloch compare?

Hillis–Steele 每轮几乎所有元素都做一次加法，共 n log₂ n − (n − 1) = 9217 次，是 O(n log n)；Blelloch 上扫和下扫各 n − 1 次，共 2046 次，是 O(n)，两者不同阶。Blelloch 的层数是 2 log₂ n = 20，比 Hillis–Steele 的 10 层多一倍，所以元素不多于并行宽度时，层数少的 Hillis–Steele 反而可能更快。In every round of Hillis–Steele nearly every element adds once, n log₂ n − (n − 1) = 9217 in all, which is O(n log n); Blelloch makes n − 1 additions in each sweep, 2046 in all, which is O(n), so the two differ in order. Blelloch has 2 log₂ n = 20 levels, twice the 10 of Hillis–Steele, so when the elements fit in the parallel width, Hillis–Steele with fewer levels may well be faster.

3. 一个 256-bin 的直方图改成私有化版本以后，什么变了？

3. What changes when a 256-bin histogram is privatized?

私有化把 n 次全局原子操作换成 n 次 shared memory 里的原子操作加上每个 block 至多 BINS 次合并。block 内的线程仍会撞上同一个 bin，所以 shared memory 里还是要用原子操作。整数原子加不会丢计数，顺序也不影响结果，朴素版本来就是对的，私有化改的是速度。Privatization trades n global atomics for n atomics in shared memory plus at most BINS merges per block. Threads within a block still collide on the same bin, so the shared-memory updates must still be atomic. Integer atomic adds lose no counts and their order does not change the result; the naive version was already correct, and privatization changes its speed.

4. 一个二维 3 × 3 模板计算，每个 block 算 16 × 16 个输出。它要从 global memory 装入多少个输入？

4. A two-dimensional 3 × 3 stencil has each block compute 16 × 16 outputs. How many inputs does it load from global memory?

半径 R = 1 的光环让块的每边多出 1 格，(16 + 2)² = 324，多读的 68 个是相邻块的边。把它们当成「缓存里自然会有」是靠不住的：它们是这个 block 必须自己装进 shared memory 的数据。每个输出读 9 个输入是不分块时的读取次数，分块正是为了让这 9 次读落在 shared memory 里，而不是 global memory。A halo of radius R = 1 adds one cell on each side, so (16 + 2)² = 324, and the extra 68 are the edges of neighbouring tiles. Counting on them to be in the cache anyway does not hold: this block has to load them into shared memory itself. Nine reads per output is the count without tiling; tiling exists so that those nine reads hit shared memory rather than global memory.
