解码一步只出一个 token，却要把全部权重和 KV 缓存读一遍，GPU 的算力大半闲着。推测解码利用这份闲置：一个便宜的草稿模型先猜几个 token，目标模型用一次前向同时检验它们，按拒绝采样的规则接受一段前缀，输出分布和逐个解码完全一样。EAGLE 把草稿排成一棵树，验证时每个节点只能看见前缀和自己的祖先，这就是树注意力掩码；验证内核再沿着树走一遍，找出最长的被接受路径。结构化输出走的是另一条热路径：xgrammar 在 CPU 上按语法算出这一步允许哪些 token，打成每 32 个 token 一个 int32 的位掩码，GPU 在采样前用一个小内核把不允许的 logits 改成 −∞。这台 Apple M5 上的 Metal 对照实测：把 16 个树节点当成一个小矩阵来验证，耗时是解码一个 token 的 2.1–3.4 倍，逐个查询打分则是 6.3–10.8 倍；掩码本身几乎不花时间（±5% 以内）；位掩码内核处理一行只要 1–2.5 µs，256 行时比浮点加法掩码快 2.2–9.2 倍，快多少取决于有多少 logits 要写成 −∞。哪些跑过、哪些没跑过：Lab B 的 Metal 程序 2026-11-01 在这台 Apple M5 上实际运行，数字原样贴出；Lab A 未运行，是 2026-11-01 根据 SGLang v0.5.22 的源码整理的。

A decode step produces one token but reads all the weights and the KV cache to do it, so most of the GPU’s arithmetic sits idle. Speculative decoding spends that idle capacity: a cheap draft model guesses a few tokens, the target model checks them all in one forward pass, a rejection-sampling rule accepts a prefix of them, and the output distribution is exactly that of decoding one token at a time. EAGLE arranges its drafts as a tree; during verification each node may see only the prefix and its own ancestors, which is the tree-attention mask, and a verification kernel then walks the tree to find the longest accepted path. Structured output is a different hot path: xgrammar works out on the CPU which tokens the grammar allows at this step, packs them into a bitmask of one int32 per 32 tokens, and before sampling a small GPU kernel sets the disallowed logits to −∞. Measured with the Metal twin on this Apple M5: verifying 16 tree nodes as one small matrix takes 2.1–3.4 times as long as decoding one token, against 6.3–10.8 times when each query is scored on its own; the mask itself costs almost nothing (within ±5%); and the bitmask kernel needs only 1–2.5 µs for one row and, at 256 rows, beats an additive float mask by 2.2–9.2 times, depending on how many logits it has to set to −∞. What was run and what was not: the Metal program of Lab B was actually run on this Apple M5 on 2026-11-01 and its numbers are pasted as they came; Lab A is not run, assembled on 2026-11-01 from the SGLang v0.5.22 source.

核心概念

Core concepts

批很小时，解码每一步都把全部权重读一遍，却只产出一个 token，GPU 的算力大半闲着。能不能一次前向就产出好几个 token，而且输出的分布和一个一个生成时完全一样？另一件事是，应用常常要求输出必须是合法的 JSON：模型自己不保证这一点，事后检查只能整段重来，而在每一步对 32000 个 token 逐个检查语法又太慢。

At small batch sizes every decode step reads all the weights once yet yields a single token, and most of the GPU’s arithmetic sits idle. Can one forward pass yield several tokens, with an output distribution exactly the same as generating them one by one? Separately, applications often require the output to be valid JSON: the model does not guarantee it, checking afterwards can only throw the whole answer away, and checking the grammar for each of 32000 tokens at every step is too slow.

概念 1 的接受规则回答前一件，概念 2 的草稿树和概念 3 的树掩码与验证内核让它高效；概念 4 的每步位掩码回答后一件。

The acceptance rule of concept 1 answers the first, and the draft tree of concept 2 with the tree mask and verification kernel of concept 3 make it efficient; the per-step bitmask of concept 4 answers the second.

1. 先起草、再验证，以及接受规则

1. Draft, then verify, and the acceptance rule

批很小的时候，解码一步的时间几乎全花在读权重上（Phase 0）。把 1 个 token 换成 γ+1 个 token 一起送进目标模型，权重仍然只读一遍，多出来的只是矩阵乘里多几行和注意力里多几个查询，时间增加得很少。推测解码就是让一个便宜的草稿模型 Mq 先依次猜出 γ 个 token，再让目标模型 Mp 用一次前向算出这 γ+1 个位置各自的分布 p。

At small batch sizes the time of a decode step goes almost entirely into reading weights (Phase 0). Feed the target model γ+1 tokens instead of 1 and the weights are still read once; what is added is a few more rows in each matmul and a few more queries in attention, so the time grows only a little. Speculative decoding lets a cheap draft model Mq guess γ tokens one after another, then has the target model Mp compute the distribution p at all γ+1 positions in one forward pass.

论文第 2.3 节的规则：从草稿分布 q 抽出 x，若 q(x) ≤ p(x) 就保留；否则以 1 − p(x)/q(x) 的概率拒绝，拒绝后改从调整过的分布 p′(x) = norm(max(0, p(x) − q(x))) 重新抽一个。附录 A.1 证明这样抽出的 x 正好服从 p。γ 个草稿依次检验，第一个被拒绝的位置用 p′ 补一个 token，全部通过时再从第 γ+1 个位置的 p 白得一个，所以一次验证产出 1 到 γ+1 个 token。若每个位置的接受概率独立、均值为 α，产出个数是一个封顶的几何变量，期望是 (1 − αγ+1) / (1 − α)（论文式 (1)）。贪心解码是它的特例：q 和 p 都是 one-hot，规则变成「草稿 token 等于目标模型的 argmax 就接受」。

The rule from section 2.3 of the paper: draw x from the draft distribution q and keep it if q(x) ≤ p(x); otherwise reject it with probability 1 − p(x)/q(x), and after a rejection draw again from the adjusted distribution p′(x) = norm(max(0, p(x) − q(x))). Appendix A.1 proves that x drawn this way follows p exactly. The γ drafts are checked in order; the first rejected position is filled with one token drawn from p′, and when all pass, one more token comes free from p at position γ+1, so one verification yields between 1 and γ+1 tokens. If the acceptance probabilities are independent with mean α, the count is a capped geometric variable with expectation (1 − αγ+1) / (1 − α) (equation (1) of the paper). Greedy decoding is the special case where q and p are both one-hot and the rule becomes: accept the draft token if it equals the target model’s argmax.

2. EAGLE 的草稿树

2. EAGLE’s draft tree

EAGLE 的草稿模型不是一个独立的小语言模型，而是一层 Transformer 解码层：它读入目标模型倒数第二层的特征和提前一步的 token 序列，自回归地预测下一个特征，再用目标模型的 LM head 得到分布（论文第 3 节）。所以草稿很便宜，也和目标模型很像。Lab A 用的 lmsys/sglang-EAGLE-llama2-chat-7B 的 config.json 写的是 LlamaForCausalLMEagle、num_hidden_layers 为 1，权重文件 1,468,043,538 字节；目标模型 meta-llama/Llama-2-7b-chat-hf 的 safetensors 合计 13,476,872,576 字节（都是 2026-11-01 从 Hugging Face 的 API 读的）。

EAGLE’s draft model is not a separate small language model but a single Transformer decoder layer: it reads the target model’s second-to-top-layer features plus the token sequence advanced by one step, predicts the next feature autoregressively, and turns it into a distribution with the target model’s LM head (section 3 of the paper). So the draft is cheap and closely resembles the target. The config.json of lmsys/sglang-EAGLE-llama2-chat-7B, used in Lab A, says LlamaForCausalLMEagle with num_hidden_layers of 1, and its weight file is 1,468,043,538 bytes; the target meta-llama/Llama-2-7b-chat-hf has 13,476,872,576 bytes of safetensors (both read from the Hugging Face API on 2026-11-01).

只猜一条链太浪费：第一个 token 一旦猜错，后面全作废。EAGLE 每一步对每个节点保留概率最高的 topk 个候选，num_steps 次草稿前向就长出一棵深度为 num_steps 的树（论文第 3.2 节：3 次前向画出一棵 10 个 token 的树）；EAGLE-2 再按「从根到这个节点的累积概率」动态挑选要保留的节点。SGLang v0.5.22 里这一段在 srt/speculative/eagle_worker_v2.py 的 draft()（第 614 行起）：每一步对草稿 logits 调 fast_topk(probs, self.topk, dim=-1)（第 837 行），最后 organize_draft_results（srt/speculative/eagle_utils.py 第 113–142 行）对所有候选的累积分数做一次 torch.topk，留下 num_draft_tokens − 1 个，按原顺序排好，连同它们的父节点表一起交出去。加上根（上一轮已经确定的那个 token），树上共有 num_draft_tokens 个节点。

Guessing a single chain is wasteful: once the first token is wrong, everything after it is thrown away. At each step EAGLE keeps the topk most probable candidates of every node, so num_steps draft forwards grow a tree of depth num_steps (section 3.2 of the paper: three forwards draw a 10-token tree), and EAGLE-2 picks which nodes to keep dynamically, by the cumulative probability from the root to each node. In SGLang v0.5.22 this is draft() in srt/speculative/eagle_worker_v2.py (from line 614): every step calls fast_topk(probs, self.topk, dim=-1) on the draft logits (line 837), and at the end organize_draft_results (lines 113–142 of srt/speculative/eagle_utils.py) runs one torch.topk over the cumulative scores of all candidates, keeps num_draft_tokens − 1 of them in their original order, and hands them over with their parent table. With the root (the token fixed by the previous round) the tree has num_draft_tokens nodes.

三个参数都不设时，_auto_choose_speculative_params（speculative_hook.py 第 1340–1371 行）按模型挑：LlamaForCausalLM 是 (5, 4, 8)，即 5 步、每步 topk 4、树上 8 个节点；DeepSeek、GPT-OSS 等和其余模型默认 (3, 1, 4)，topk 为 1 就是一条链。SGLang 的文档说要么三个都不设，要么三个都设。topk 为 1 时还有一条快路径：srt/speculative/eagle_worker_common.py 第 448–465 行在 QLEN_ONLY 掩码模式下改调 build_chain_tree，因为一条链的掩码就是普通的因果掩码。

When none of the three is set, _auto_choose_speculative_params (lines 1340–1371 of speculative_hook.py) picks by model: LlamaForCausalLM gets (5, 4, 8), meaning 5 steps, topk 4 per step and 8 nodes in the tree; DeepSeek, GPT-OSS and the rest default to (3, 1, 4), and topk 1 is a chain. SGLang’s documentation says to set all three or none. Topk 1 also has a fast path: lines 448–465 of srt/speculative/eagle_worker_common.py call build_chain_tree instead in QLEN_ONLY mask mode, because the mask of a chain is the ordinary causal mask.

3. 树注意力掩码和验证内核

3. The tree-attention mask and the verification kernel

验证时，树上的 N 个节点作为 N 个查询一起送进目标模型。每个节点只该看见前缀和自己的祖先：它的兄弟和堂兄弟是另一种猜法，看见了就算错了。所以普通的因果掩码不行，要一张自定义掩码。SGLang 的默认布局 TreeMaskMode.FULL_MASK（eagle_utils.py 第 145–154 行）给每个请求一块 N 行 × (seq_len + N) 列的 bool 矩阵，按请求首尾相接，总长 seq_lens_sum × N + N × N × bs（第 208–219 行）；前缀那 seq_len 列全是 True，后面 N × N 的树块里，第 i 行只在 i 的祖先和 i 自己那几列是 True。

For verification, the N nodes of the tree go into the target model together as N queries. Each node should see only the prefix and its own ancestors: its siblings and cousins are a different guess, and seeing them would be wrong. So an ordinary causal mask will not do, and a custom mask is needed. SGLang’s default layout, TreeMaskMode.FULL_MASK (lines 145–154 of eagle_utils.py), gives each request a bool matrix of N rows by seq_len + N columns, requests laid end to end, seq_lens_sum × N + N × N × bs in total (lines 208–219); the seq_len prefix columns are all True, and in the N × N tree block row i is True only in the columns of i’s ancestors and i itself.

这张表由一个 CUDA 内核一次填好：kernels/jit/include/sgl_kernel/speculative/eagle.cuh 的 build_tree_efficient（第 35–131 行），经 kernels/ops/speculative/tree.py 的 JIT 模块调用。一个线程块负责一个请求，线程 i 负责节点 i：先把自己这一行的树块清零、对角线置 True，再沿父节点表一路往上走，把经过的每个祖先那一列置 True，走了几步就是深度，位置写成 seq_len + 深度（RoPE 要用）。线程 0 另外把树改写成两张链表：retrive_next_token（第一个孩子）和 retrive_next_sibling（下一个兄弟），后面的验证内核就靠它们走树。

One CUDA kernel fills this table in one go: build_tree_efficient in kernels/jit/include/sgl_kernel/speculative/eagle.cuh (lines 35–131), called through the JIT module in kernels/ops/speculative/tree.py. One thread block handles one request and thread i handles node i: it clears its own row of the tree block and sets the diagonal True, then walks up the parent table, setting the column of every ancestor it passes to True; the number of steps is the depth, and the position is written as seq_len + depth (RoPE needs it). Thread 0 also rewrites the tree as two linked lists, retrive_next_token (the first child) and retrive_next_sibling (the next sibling), which the verification kernel later uses to walk the tree.

目标模型的这次前向是 TARGET_VERIFY 模式。FlashInfer 后端把它当作一次预填充：srt/layers/attention/flashinfer_backend.py 第 1286–1292 行在验证模式且带 custom_mask 时建预填充的 wrapper，第 2346 行把掩码作为 custom_mask 传给 begin_forward（即 plan()）；行指针和 KV 下标由 EagleVerifyInput.generate_attn_arg_prefill 构造（srt/speculative/eagle_info.py 第 90–148 行），每个请求 N 个查询、seq_len + N 个键，正是 Phase 1 的 CSR 合同。FlashInfer v0.7.1 的文档字符串说，只给 bool 掩码时它会先打包成位（flashinfer/prefill.py 第 1342–1353 行，打包在第 1458–1462 行：packbits(..., bitorder="little")），内核按 MaskMode.CUSTOM 读这些位。验证步也能被捕获成 CUDA 图：第 1094 行预先分配了图用的 cuda_graph_custom_mask。

After the forward pass comes the verification kernel, entered through eagle_sample in eagle_utils.py (from line 741). When every request is greedy, it takes torch.argmax over each node’s logits (line 868) and then calls VerifyTreeGreedy (lines 214–256 of eagle.cuh): one thread block per request, starting at the root, searching the current node’s child list for the child whose token equals the target model’s argmax at the current node; if one is found it is accepted and the walk descends, otherwise the walk stops. Finally the target’s argmax at the last accepted node is written as the free token, so accept len is the number of accepted drafts plus 1. Requests with a temperature go through TreeSpeculativeSamplingTargetOnly instead (from line 39 of kernels/jit/include/sgl_kernel/speculative/sampling.cuh, called at line 1023 of eagle_utils.py): siblings are tried in order and accepted when the cumulative target probability passes a random number; a rejected token is recorded in draft_probs, and the last token is drawn from relu(p − the rejected part). Without --speculative-use-rejection-sampling the draft is treated as a deterministic guess, and draft_probs starts as all zeros (lines 1000–1004).

多验证 N 个查询要花多少？在注意力里，N 个查询共享同一份 KV，KV 只要读一遍；但每个键要和 N 个查询各做一次点积。逐个查询打分（每个查询一次 SIMD 归约）时，算术就成了瓶颈；把 N 个查询当成一个 N × 128 的矩阵，Q·Kᵀ 和 P·V 变成小矩阵乘，在 NVIDIA 上由 Tensor Core 做，在 Apple GPU 上由 simdgroup_matrix 做，开销就小得多。Lab B 量的就是这个差别；掩码本身每格只是一次读和一个判断，量出来几乎不花时间。

What does it cost to verify N queries? In attention the N queries share one copy of the KV, so the KV is read once, but every key needs a dot product with each of the N queries. Score each query on its own (one SIMD reduction per query) and arithmetic becomes the bottleneck; treat the N queries as one N × 128 matrix and Q·Kᵀ and P·V become small matrix products, done by Tensor Cores on NVIDIA and by simdgroup_matrix on the Apple GPU, at much lower cost. Lab B measures exactly this difference; the mask itself is one read and one test per cell, and measures as nearly free.

4. 用 xgrammar 做结构化输出：每步一个位掩码

4. Structured output with xgrammar: one bitmask per step

要求模型输出合法的 JSON（或满足一个正则、一个 EBNF 语法），做法是约束解码：每一步先算出哪些 token 接在已生成的文本后面仍然合法，把其余 token 的 logits 设成 −∞，softmax 之后它们的概率就是 0，合法 token 之间的相对概率不变（XGrammar 论文第 2 节）。语法是上下文无关的，所以执行它要一台下推自动机；难点是每一步都要对整个词表检查一遍。XGrammar 把词表分成「上下文无关」的 token（只看自动机栈顶就能决定，预处理时算好，存进自适应 token 掩码缓存）和「上下文相关」的 token（运行时用持久化栈检查），掩码按允许多还是拒绝多选最省的存法（第 3.1 节）；运行时它在 CPU 上算掩码，和 GPU 上的前向重叠，只在采样前同步一次（第 3.5 节）。

To make a model emit valid JSON (or match a regex, or an EBNF grammar), use constrained decoding: at every step, work out which tokens can still legally follow the text so far, and set the logits of all the others to −∞; after the softmax their probability is 0, and the relative probabilities of the legal tokens are unchanged (section 2 of the XGrammar paper). The grammar is context-free, so running it takes a pushdown automaton, and the hard part is checking the whole vocabulary at every step. XGrammar splits the vocabulary into context-independent tokens (decided by the top of the automaton’s stack alone, computed in preprocessing and stored in an adaptive token mask cache) and context-dependent tokens (checked at run time with a persistent stack), storing each mask in whichever form is cheapest, accept-heavy or reject-heavy (section 3.1); at run time it computes the mask on the CPU, overlapped with the forward pass on the GPU, and synchronizes only before sampling (section 3.5).

常见误解

Common misconceptions

  • 误解：推测解码用质量换速度，输出会偏向草稿模型。→ 实际：论文附录 A.1 证明按接受规则抽出的 token 正好服从目标分布；贪心时输出与目标模型逐个 argmax 完全相同。
  • 误解：验证一棵树要对每条分支各跑一次目标模型。→ 实际：树上所有节点作为 N 个查询一次送进目标模型，靠树注意力掩码让每个节点只看见自己的祖先。
  • 误解：结构化输出的位掩码内核要把整行 logits 读出来再写回。→ 实际：它只读 V/8 字节的掩码，只写被屏蔽的那些位置；允许的 token 原封不动。
  • Myth: speculative decoding trades quality for speed, biasing the output towards the draft model. → Fact: Appendix A.1 of the paper proves that tokens drawn by the acceptance rule follow the target distribution exactly, and under greedy decoding the output is identical to the target’s token-by-token argmax.
  • Myth: verifying a tree takes one target pass per branch. → Fact: all the tree’s nodes go into the target together as N queries, and the tree-attention mask lets each node see only its own ancestors.
  • Myth: the structured-output bitmask kernel reads the whole logits row and writes it back. → Fact: it reads only the V/8-byte mask and writes only the masked positions; allowed tokens are left untouched.

let H = 32, D = 128, NT = 16                 // Llama-2-7B: 32 heads, head_dim 128; 16 draft tokens per tree
// The draft tree: node 0 is the root (the last accepted token), parent[i] < i.
let parent: [Int] = [-1, 0, 0, 0, 0, 1, 1, 1, 2, 2, 3, 5, 5, 6, 8, 5]

func source(nq: Int) -> String { return """
#include <metal_stdlib>
#include <metal_simdgroup_matrix>
using namespace metal;
constant uint NQ = \(nq);                    // queries per head in the per-query kernel
constant uint D4 = 32;                       // head_dim 128 = 32 float4, one per SIMD lane

inline bool allowed(device const uchar* m, uint mode, uint i, uint j, uint S) {
    if (mode == 0) return true;                              // no mask
    uint idx = i * S + j;                                    // FULL_MASK layout: row i, column j
    if (mode == 1) return m[idx] != 0;                       // one bool per cell
    return (m[idx >> 3] >> (idx & 7)) & 1;                   // bit-packed, little bit order
}

// Per-query kernel: one threadgroup per head, 8 SIMD groups split the keys, each lane holds 4 dims.
// Each key is loaded once, but every query gets its own dot product and SIMD reduction.
kernel void attn_per_query(device const float4* q [[buffer(0)]], device const float4* k [[buffer(1)]],
                           device const float4* v [[buffer(2)]], device const uchar* mask [[buffer(3)]],
                           device float* part [[buffer(4)]], constant uint& S [[buffer(5)]],
                           constant uint& mode [[buffer(6)]], constant uint& chunk [[buffer(7)]],
                           uint2 tgp [[threadgroup_position_in_grid]], uint2 ntg [[threadgroups_per_grid]],
                           uint sg [[simdgroup_index_in_threadgroup]], uint lane [[thread_index_in_simdgroup]]) {
    uint h = tgp.x, sp = tgp.y, P = ntg.y, j0 = sp * chunk, j1 = min(S, j0 + chunk);
    threadgroup float tm[8], tl[8];
    threadgroup float4 tacc[8][32];
    float4 qv[NQ], acc[NQ];
    float mx[NQ], l[NQ];
    const float scale = rsqrt(128.0f);
    for (uint i = 0; i < NQ; i++) {
        qv[i] = q[(h * NQ + i) * D4 + lane] * scale;
        acc[i] = 0; mx[i] = -INFINITY; l[i] = 0;
    }
    for (uint j = j0 + sg; j < j1; j += 8) {
        float4 kk = k[(h * S + j) * D4 + lane], vv = v[(h * S + j) * D4 + lane];
        for (uint i = 0; i < NQ; i++) {
            float s = simd_sum(dot(qv[i], kk));
            if (!allowed(mask, mode, i, j, S)) continue;     // a masked cell never enters the softmax
            float m2 = max(mx[i], s), c = exp(mx[i] - m2), p = exp(s - m2);
            l[i] = l[i] * c + p; acc[i] = acc[i] * c + p * vv; mx[i] = m2;
        }
    }
    for (uint i = 0; i < NQ; i++) {                          // merge the 8 partial softmax states
        if (lane == 0) { tm[sg] = mx[i]; tl[sg] = l[i]; }
        tacc[sg][lane] = acc[i];
        threadgroup_barrier(mem_flags::mem_threadgroup);
        if (sg == 0) {
            float M = -INFINITY;
            for (uint g = 0; g < 8; g++) M = max(M, tm[g]);
            float L = 0; float4 a = 0;
            for (uint g = 0; g < 8; g++) { float w = (tm[g] == -INFINITY) ? 0.0f : exp(tm[g] - M); L += tl[g] * w; a += tacc[g][lane] * w; }
            device float* pp = part + ((h * P + sp) * NQ + i) * 130;   // partial: max, sum, 128 values
            if (lane == 0) { pp[0] = M; pp[1] = L; }
            ((device float4*)(pp + 2))[lane] = a;
        }
        threadgroup_barrier(mem_flags::mem_threadgroup);
    }
}

// Tile kernel: the 16 tree queries as one 16 x 128 matrix. Per block of 8 keys, S = Q K^T and O += P V
// are 8 x 8 simdgroup matrix products, the way a prefill kernel with a custom mask treats them.
constant uint NSG = 4;
kernel void attn_tree_tile(device const float* q [[buffer(0)]], device const float* k [[buffer(1)]],
                           device const float* v [[buffer(2)]], device const uchar* mask [[buffer(3)]],
                           device float* part [[buffer(4)]], constant uint& S [[buffer(5)]],
                           constant uint& mode [[buffer(6)]], constant uint& chunk [[buffer(7)]],
                           uint2 tgp [[threadgroup_position_in_grid]], uint2 ntg [[threadgroups_per_grid]],
                           uint sg [[simdgroup_index_in_threadgroup]], uint lane [[thread_index_in_simdgroup]],
                           uint tid [[thread_index_in_threadgroup]]) {
    uint h = tgp.x, sp = tgp.y, P = ntg.y, j0 = sp * chunk, j1 = min(S, j0 + chunk);
    threadgroup float sS[NSG][128];          // this SIMD group's 16 x 8 score block, then P
    threadgroup float sC[NSG][2][64];        // two 8 x 8 diagonal rescale matrices
    threadgroup float sM[NSG][16], sL[NSG][16], sLt[16];
    threadgroup float sO[16 * 128], sQ[16 * 128];
    for (uint x = tid; x < NSG * 128; x += NSG * 32) ((threadgroup float*)sC)[x] = 0;
    for (uint x = tid; x < 16 * 128; x += NSG * 32) { sO[x] = 0; sQ[x] = q[h * 16 * 128 + x]; }
    threadgroup_barrier(mem_flags::mem_threadgroup);

    device const float* kh = k + h * S * 128;
    device const float* vh = v + h * S * 128;
    simdgroup_float8x8 ot[2][16];            // the 16 x 128 output block stays in registers; Q is read from sQ
    for (uint r = 0; r < 2; r++) for (uint c = 0; c < 16; c++) ot[r][c] = make_filled_simdgroup_matrix<float, 8, 8>(0.0f);
    const float scale = rsqrt(128.0f);
    float m = -INFINITY, l = 0;              // lane i < 16 owns row i
    for (uint base = j0 + sg * 8; base < j1; base += NSG * 8) {
        simdgroup_float8x8 s0 = make_filled_simdgroup_matrix<float, 8, 8>(0.0f), s1 = s0, kt, qa, qb;
        for (uint c = 0; c < 16; c++) {
            simdgroup_load(kt, kh + base * 128 + c * 8, 128, ulong2(0, 0), true);   // 8 dims x 8 keys
            simdgroup_load(qa, sQ + c * 8, 128); simdgroup_load(qb, sQ + 8 * 128 + c * 8, 128);
            simdgroup_multiply_accumulate(s0, qa, kt, s0);
            simdgroup_multiply_accumulate(s1, qb, kt, s1);
        }
        simdgroup_store(s0, sS[sg], 8); simdgroup_store(s1, sS[sg] + 64, 8);
        simdgroup_barrier(mem_flags::mem_threadgroup);
        if (lane < 16) {                                     // online softmax for row `lane`
            float s[8], mn = m;
            for (uint c = 0; c < 8; c++) {
                s[c] = allowed(mask, mode, lane, base + c, S) ? sS[sg][lane * 8 + c] * scale : -INFINITY;
                mn = max(mn, s[c]);
            }
            float cr = (mn == -INFINITY) ? 1.0f : exp(m - mn), sum = 0;
            for (uint c = 0; c < 8; c++) { float p = (s[c] == -INFINITY) ? 0.0f : exp(s[c] - mn); sS[sg][lane * 8 + c] = p; sum += p; }
            l = l * cr + sum; m = mn;
            sC[sg][lane / 8][(lane % 8) * 9] = cr;
        }
        simdgroup_barrier(mem_flags::mem_threadgroup);
        simdgroup_float8x8 p0, p1, c0, c1, vt;
        simdgroup_load(p0, sS[sg], 8); simdgroup_load(p1, sS[sg] + 64, 8);
        simdgroup_load(c0, sC[sg][0], 8); simdgroup_load(c1, sC[sg][1], 8);
        for (uint c = 0; c < 16; c++) {
            simdgroup_load(vt, vh + base * 128 + c * 8, 128);                      // 8 keys x 8 dims
            simdgroup_multiply(ot[0][c], c0, ot[0][c]);                             // rescale old rows
            simdgroup_multiply(ot[1][c], c1, ot[1][c]);
            simdgroup_multiply_accumulate(ot[0][c], p0, vt, ot[0][c]);
            simdgroup_multiply_accumulate(ot[1][c], p1, vt, ot[1][c]);
        }
        simdgroup_barrier(mem_flags::mem_threadgroup);
    }
    // Merge the NSG partial states: rescale each to the common row max, then add them up in sO.
    if (lane < 16) { sM[sg][lane] = m; sL[sg][lane] = l; }
    threadgroup_barrier(mem_flags::mem_threadgroup);
    if (lane < 16) {
        float M = -INFINITY, Lt = 0;
        for (uint g = 0; g < NSG; g++) M = max(M, sM[g][lane]);
        for (uint g = 0; g < NSG; g++) if (sM[g][lane] != -INFINITY) Lt += sL[g][lane] * exp(sM[g][lane] - M);
        sC[sg][lane / 8][(lane % 8) * 9] = (m == -INFINITY) ? 0.0f : exp(m - M);
        if (sg == 0) sLt[lane] = Lt;
    }
    threadgroup_barrier(mem_flags::mem_threadgroup);
    simdgroup_float8x8 c0, c1, t, eye = simdgroup_float8x8(1.0f);
    simdgroup_load(c0, sC[sg][0], 8); simdgroup_load(c1, sC[sg][1], 8);
    for (uint g = 0; g < NSG; g++) {
        if (sg == g) {
            for (uint r = 0; r < 2; r++) for (uint c = 0; c < 16; c++) {
                simdgroup_multiply(ot[r][c], r == 0 ? c0 : c1, ot[r][c]);
                simdgroup_load(t, sO + r * 8 * 128 + c * 8, 128);
                simdgroup_multiply_accumulate(t, eye, ot[r][c], t);
                simdgroup_store(t, sO + r * 8 * 128 + c * 8, 128);
            }
        }
        threadgroup_barrier(mem_flags::mem_threadgroup);
    }
    for (uint x = tid; x < 16 * 128; x += NSG * 32) {       // partial: max, sum, 128 unnormalized values
        device float* pp = part + ((h * P + sp) * 16 + x / 128) * 130;
        if (x % 128 == 0) { float M = -INFINITY; for (uint g = 0; g < NSG; g++) M = max(M, sM[g][x / 128]); pp[0] = M; pp[1] = sLt[x / 128]; }
        pp[2 + x % 128] = sO[x];
    }
}

// Combine the P split partials of each (head, query) row: rescale to the common max, add, divide.
kernel void combine(device const float* part [[buffer(0)]], device half* o [[buffer(1)]],
                    constant uint& P [[buffer(2)]], constant uint& nq [[buffer(3)]],
                    uint2 g [[thread_position_in_grid]]) {
    uint x = g.x, row = g.y, h = row / nq, i = row % nq;    // x = one of 128 dims
    float M = -INFINITY, L = 0, a = 0;
    for (uint p = 0; p < P; p++) M = max(M, part[((h * P + p) * nq + i) * 130]);
    for (uint p = 0; p < P; p++) {
        device const float* pp = part + ((h * P + p) * nq + i) * 130;
        if (pp[0] == -INFINITY) continue;                    // an empty split, or a row it fully masks
        float w = exp(pp[0] - M); L += pp[1] * w; a += pp[2 + x] * w;
    }
    o[row * 128 + x] = half(a / L);
}

// xgrammar-style bitmask: bit t of row r is 1 when token t is allowed. Only disallowed logits are written.
kernel void apply_bitmask(device float* logits [[buffer(0)]], device const uint* bm [[buffer(1)]],
                          constant uint& V [[buffer(2)]], constant uint& W [[buffer(3)]],
                          uint2 g [[thread_position_in_grid]]) {
    uint t = g.x, r = g.y;
    if (t >= V) return;
    if (((bm[r * W + (t >> 5)] >> (t & 31)) & 1) == 0) logits[r * V + t] = -INFINITY;
}

// The dense alternative: an additive float mask (0 or -inf) per token, read and added to every logit.
kernel void add_float_mask(device float* logits [[buffer(0)]], device const float* fm [[buffer(1)]],
                           constant uint& V [[buffer(2)]], uint2 g [[thread_position_in_grid]]) {
    uint t = g.x, r = g.y;
    if (t >= V) return;
    logits[r * V + t] += fm[r * V + t];
}
"""
}

func time(reps: Int, _ encode: (MTLComputeCommandEncoder) -> Void) -> Double {
    var ts: [Double] = []
    for k in 0..<(warm + N) {
        let cb = queue.makeCommandBuffer()!, enc = cb.makeComputeCommandEncoder()!
        for _ in 0..<reps { encode(enc) }
        enc.endEncoding(); cb.commit(); cb.waitUntilCompleted()
        if k >= warm { ts.append((cb.gpuEndTime - cb.gpuStartTime) / Double(reps)) }
    }
    return ts.sorted()[N / 2]
}

func floatBuf(_ count: Int) -> MTLBuffer {
    let b = dev.makeBuffer(length: count * 4, options: .storageModeShared)!
    let p = b.contents().bindMemory(to: Float.self, capacity: count)
    for i in 0..<count { p[i] = Float.random(in: -1...1, using: &rng) }
    return b
}

    // CPU reference: node i attends to the prefix and to its own path in the tree, nothing else.
    func pathRef(_ h: Int, _ i: Int) -> [Float] {
        let qp = fp(q), kp = fp(k), vp = fp(v)
        let keys = Array(0..<L) + (0..<NT).filter { anc[i][$0] }.map { L + $0 }
        var s = [Float](repeating: 0, count: keys.count)
        for (n, j) in keys.enumerated() {
            var d: Float = 0
            for x in 0..<D { d += qp[(h * NT + i) * D + x] * kp[(h * S + j) * D + x] }
            s[n] = d / Float(D).squareRoot()
        }
        let m = s.max()!; var sum: Float = 0; var out = [Float](repeating: 0, count: D)
        for (n, j) in keys.enumerated() {
            let p = exp(s[n] - m); sum += p
            for x in 0..<D { out[x] += p * vp[(h * S + j) * D + x] }
        }
        return out.map { $0 / sum }
    }
    var refs: [[Float]] = []
    for h in [0, H - 1] { for i in 0..<NT { refs.append(pathRef(h, i)) } }
    func maxErr() -> String {
        let op = o.contents().bindMemory(to: Float16.self, capacity: H * NT * D); var e: Float = 0, n = 0
        for h in [0, H - 1] { for i in 0..<NT {
            for x in 0..<D {                           // a NaN must show up, not vanish inside max()

  3. 先看正确性：带掩码的两种树验证和 CPU 参考的最大差在 4e-6 到 6e-5 之间，是 FP16 输出的舍入（K、V 用 FP32 存，合并内核把结果写成 half）；三次运行都一样。不带掩码时差到 3e-2（L = 256）到 5e-4（L = 16384）：每个节点多看了 16 个键里本不该看的那些，前缀越长，这几个键在注意力里的份额越小，误差也越小，但结果始终是错的。Correctness first: the two masked tree verifies differ from the CPU reference by 4e-6 to 6e-5 at most, the rounding of the FP16 output (K and V are stored in FP32, and the combine kernel writes the result as half), in all three runs. 1. Greedy verification of a tree: after the root the target’s argmax is A, and the root has children A and B; after A the argmax is C, and A has only the child D. How many tokens does this round commit?

VerifyTreeGreedy 在根的孩子里找到等于 argmax 的 A，接受；在 A 的孩子里找不到 C（只有 D），停下，再把目标模型在最后一个被接受节点 A 上的 argmax C 写成白得的 token。所以是 A 和 C 两个。D 和 C 不同，不会被接受；被拒绝也不会让已经接受的 A 作废。VerifyTreeGreedy finds A, equal to the argmax, among the root’s children and accepts it; among A’s children it finds no C (only D), so it stops and writes the target’s argmax at the last accepted node A, which is C, as the free token. That makes two, A and C. D differs from C and is not accepted, and a rejection never discards the A that was already accepted.
